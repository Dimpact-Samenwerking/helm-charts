## openvtb (new, 0.2.0, chart 0.2.0)

New optional component, `openvtb.enabled: false` by default; all keys below are new. Nothing
changes for environments that leave it disabled.

When `openvtb.enabled: true`, these values are **mandatory** (no usable default):

| Key | Why | Default |
| --- | --- | --- |
| `openvtb.configuration.oidcUrl` | Public https URL; Keycloak redirect URIs derive from it. The render **fails** when empty or an `example.nl` URL (guard in `keycloak-podiumd-realm-config.yaml`). | `""` (guard) |
| `openvtb.settings.database.host` | PostgreSQL server | `""` |
| `openvtb.settings.database.name` | Database name | `""` |
| `openvtb.settings.database.username` | Database user | `""` |
| `openvtb.settings.database.password` | Database password (pipeline-injected) | `""` |
| `openvtb.settings.secretKey` | Django `SECRET_KEY` | `""` |
| `openvtb.settings.allowedHosts` | Must include the public host from `oidcUrl` (default is only the in-cluster service name) | `openvtb.podiumd.svc.cluster.local` |
| `openvtb.image.repository` | Point at the ACR mirror in Azure environments (pod creation is blocked otherwise) | `maykinmedia/open-vtb` |
| Azure file share `openvtb` | Static PV, must pre-exist (infra, not a value) | n/a |

Only `openvtb.configuration.oidcUrl` is enforced by a render-time guard; the others fail at
runtime when missing.
