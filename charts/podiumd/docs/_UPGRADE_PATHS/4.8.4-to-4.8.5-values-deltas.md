# Values deltas — PodiumD 4.8.4 → 4.8.5

**Environments without `zac.brpApi.protocollering.verwerking.header` set 
need no gemeente `podiumd.yml` changes for this hop.**

## BRP protocollering already enabled for iConnect: set `extendWithZaaktype: true`

Chart 1.0.297 adds `verwerking.extendWithZaaktype`. The chart ships its own
default (`""`), so there's **no render risk** either way (verified by
rendering with the key absent from every layer — it still renders
successfully). This is a correctness fix, not a blocker: the default/unset
value behaves as "not extended," which is wrong for iConnect. Only applies
to environments that already have BRP protocollering configured for
**iConnect** (see [4.8.1-to-4.8.2-gemeente-specific.md](4.8.1-to-4.8.2-gemeente-specific.md#zac--brp-protocollering-configuration-per-gemeente)).

| Action | Key | Notes |
| --- | --- | --- |
| **add** | `zac.brpApi.protocollering.verwerking.extendWithZaaktype: true` | iConnect only — register must be extended with the zaaktype. eServices/2Secure environments can leave the `false` default. |

Example (iConnect environment):

```yaml
# 4.8.4                                          # 4.8.5
zac:                                              zac:
  brpApi:                                           brpApi:
    protocollering:                                     protocollering:
      verwerking:                                         verwerking:
        header: "x-verwerking"                              header: "x-verwerking"
        register: "DigitaleDienstverlening"                 register: "DigitaleDienstverlening"
                                                             extendWithZaaktype: true
```

Environments with `verwerking.header: ""` (the chart default — protocollering
not configured this way) are unaffected; podiumd's own chart default already
sets `extendWithZaaktype: false` alongside it.

## Do not enable ZAC PKCE on this release - no action needed

Chart 1.0.297 templates a new `zac.auth.enablePkce` key (`AUTH_ENABLE_PKCE`),
but the image pinned in podiumd 4.8.5 is **5.0.2**, which has no PKCE
support at all (checked the actual v5.0.2 app source — added later, in the
5.1.x line). `zac.auth.pkceEnabled`/`zac.auth.enablePkce` both stay at their
`false` defaults; don't turn them on for ZAC yet — it would either do
nothing (`enablePkce` alone) or break login (`pkceEnabled` alone, since ZAC
5.0.2 won't send a PKCE code verifier that Keycloak would then require).

## No action needed (informational)

- `additionalAllowedFileTypes` was removed from the ZAC chart entirely; no
  gemeente values reference it.
- New pod/container security-context hardening (ZAC main pod, OPA sidecar,
  Gotenberg sidecar, `signaleren` CronJob) applies automatically — no
  gemeente `podiumd.yml` override exists for these fields to conflict with.
- OPA, Gotenberg and Solr sidecar image pins are **unchanged** this release
  (`1.17.1-static` / `8.34.0` / `9.10.1-slim`) — the chart's bundled
  defaults moved further ahead (tested against ZAC 5.5.0), but podiumd
  deliberately didn't follow since the pinned ZAC image stays on 5.0.2.
