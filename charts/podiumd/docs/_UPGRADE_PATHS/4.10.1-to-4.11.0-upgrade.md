> targets: <https://dimpact.atlassian.net/wiki/spaces/PCP/pages/7602191/Releases+PodiumD>.

## C. Per environment, before the deploy day

### C1. Open Notificaties: subscribe to kanaal `autorisaties`

Open Notificaties keeps its own copy of each client's Applicatie from the
Autorisaties API (Open Zaak), and refreshes or deletes it only when an
autorisaties notification reaches its own `/api/v1/callbacks`. Without that
abonnement, a client whose rights are changed or revoked in Open Zaak keeps
its old rights in Open Notificaties (podiumd-chart-44). Its `/view-config/`
then shows "Listens to AC notifications? Nee".

In `podiumd.yml`, under `opennotificaties.configuration.data`, add what the
commented example in the chart's `values.yaml` shows:

1. a `zgw_consumers` service `notificaties-api` for Open Notificaties itself,
   with client `open-notificaties` and its secret;
2. an item in `notifications_abonnementen_config` with a new UUID, callback
   `https://<opennotificaties>/api/v1/callbacks`, kanaal `autorisaties`, and
   as `auth` `Bearer <JWT>`: a ZGW JWT of client `open-notificaties`, signed
   with its secret;
3. `notifications_config` with `notifications_api_service_identifier:
   notificaties-api`, and `notifications_subscriptions_config` with one item
   that has the same UUID and channel `autorisaties`.

After the deploy, `/view-config/` shows "Listens to AC notifications? Ja".

## E. After the deploy

### E1. Open Zaak: documents that lost their content

Open Zaak 1.31.0 fixes three bugs that could replace a document's content with
another document's, without an error. Look for documents that were hit, once
per environment.

- **When:** after `helm upgrade`, once the `openzaak` pod runs 1.31.1.
- **Run twice:** yes. The command only reads, also on a live environment.
- **On failure:** nothing has changed; run it again.
- **Rights:** `kubectl exec` in the namespace.

With `CTX` the cluster context and `NS` the namespace:

```bash
kubectl --context "$CTX" -n "$NS" exec deploy/openzaak -- \
  python src/manage.py detect_overwritten_documents \
  > "report-openzaak-$NS.tsv" 2> "summary-openzaak-$NS.txt"
cat "summary-openzaak-$NS.txt"
```

The summary has a count per class; the report has one line per document:

| Class | What to do |
| --- | --- |
| **Affected** | Ask the application that created the document (ZAC, Open Formulieren, ...) to upload it again. Expect few or none. |
| **Possible** | Compare the document with the original in the application that uploaded it. |
| **Unlikely** | Nothing; keep the report. |

Background, and the environments that do not use the `filesystem` backend:
[Reference: Open Zaak 1.31](#reference-open-zaak-131).

### E2. Open Klant: smoke test the clients

Open Klant 2.16.0 no longer generates `nummer` for a klantcontact, an
interne taak or a partij; a client that shows it gets an empty field. After
`helm upgrade`, per environment:

- KISS: register a contactmoment and open it again; create a contactverzoek.
- ITA: open a new interne taak.

Both only read and write test data; repeat them as often as needed. Background:
[Reference: Open Klant 2.19](#reference-open-klant-219).

### E3. PABC: add the application role `zaakspecifiek_geautoriseerd`

ZAC opens a zaak of a zaaktype with the roltype "Zaakspecifiek geautoriseerde
medewerker" only to medewerkers who have the application role
`zaakspecifiek_geautoriseerd` next to a base role for that zaaktype
(podiumd-chart-43). The chart now creates the role for a new PABC, but the
migrations Job skips an application that already exists, with its roles. So,
once per environment, in the PABC UI:

1. Open the application `zaakafhandelcomponent`.
2. Add the application role `zaakspecifiek_geautoriseerd`, if it is not there.

With `pabc.seedJob.enabled: true` the seed Job runs again at this upgrade,
because `files/pabc-dataset.json` changed. It replaces all PABC content with
the dataset, which now holds the role. Grant the role in a mapping only where
the gemeente uses zaakspecifieke autorisatie.

## Changes that need no action

- **Open Zaak 1.31.1 fixes stale `ETag`s**: a conditional request no longer
  gets `304 Not Modified` for a changed resource. A response to `?expand=` has
  no `ETag`, and a request PostgreSQL cancels for a deadlock gets `503` with
  `Retry-After: 1` instead of `500`.
- **The Open Zaak worker's liveness ConfigMap is created by podiumd**
  (`templates/openzaak-celery-liveness-configmap.yaml`): charts 1.15.0 and
  1.16.0 need it but do not create it
  ([Reference: Open Zaak 1.31](#reference-open-zaak-131)).
- **Open Zaak chart 1.16.0 adds a startup probe** to the worker. Beat probes
  stay off (`beat.probesEnabled` defaults to `false`). The chart turns flower
  on by default; podiumd keeps it off.
- **Open Klant's Celery result backend is set** (Redis db 8): chart 1.14.2
  reads `settings.celery.resultBackend` instead of the misspelled
  `resultBackendl`, which podiumd now uses. Before, it was empty.
- **Open Klant's configuration job is a Helm hook** (chart 1.14.2), deleted
  before the next run; `configuration.job.ttlSecondsAfterFinished` is gone.
- **Open Klant chart 1.14.2 turns Flower on by default**; podiumd keeps it off.
- **Open Klant logs every API request** (`LOG_REQUESTS` is `True` since
  2.17.0) and no longer stores outgoing request bodies.
- **ZAC's office converter (Gotenberg) gets 50 s per conversion** instead of
  30 s (`zac.office_converter.env.API_TIMEOUT`), so very long Word documents
  convert instead of failing with 503 (podiumd-chart-40). It stays below the
  edge's read timeout of about 60 s.
- **Open VTB runs with `allowPrivilegeEscalation: false` and the
  `RuntimeDefault` seccomp profile**, in the app and its configuration Job,
  like the other Maykin apps (security review WH-02).
- **Every `emptyDir` of podiumd's own templates has `sizeLimit: 64Mi`**
  (security review WH-12): the Keycloak, PABC, Objecten, Open Inwoner, Open
  Formulieren, OpenBao and Redis Jobs, the KISS adapter, and the legacy
  api-proxy. A pod that writes more to such a volume is evicted.
- **The example `zac.zgwApis.url` is `https://open-zaak.example.nl`** instead
  of `http://open-zaak.internal` (security review NW-18). Every environment
  sets its own value.
- **The Keycloak Jobs pass secrets to `curl` on stdin** instead of on its
  command line, where any process on the node could read them (security
  review SD-09b): the `keycloak-operator` client secret, the `podiumd-admin`
  password and the client update body.
- **Keycloak sends no `X-XSS-Protection` header** in the master and podiumd
  realms, and the realm import no longer sets the offline-session maximum
  lifespan, which no client uses because offline access is disabled (security
  review IA-06).
- **Podiumd's own workloads no longer mount a ServiceAccount token**
  (`automountServiceAccountToken: false`, security review WH-08), except the
  Jobs that use the Kubernetes API with their own Role: the Redis labeller
  and pre-delete hook, and ZAC's restart after the Open Zaak configuration.

## Reference: Open Zaak 1.31

### Documents that lost their content

Open Zaak 1.31.0 fixes three bugs. Which ones could hit an environment depends
on `openzaak.settings.documentApiBackend` (podiumd's default is `filesystem`):

| Backend | Large file uploads (since 1.8.0) | Bulk import (since 1.13.0) | Same-name saves (since 1.27.0) |
| --- | --- | --- | --- |
| `filesystem` | affected | affected | not affected |
| `azure_blob_storage` | affected | not affected | not affected |
| `s3_storage` | affected | not affected | affected |

1. **Large file uploads:** documents with the same `bestandsnaam`, uploaded in
   `bestandsdelen` and unlocked at the same time.
2. **Bulk import:** files with the same name, imported in the same month as
   another file or document with that name.
3. **Same-name saves:** documents with the same name, saved at the same time.

An environment that switched backends checks every backend it used since
Open Zaak 1.8.0. On `azure_blob_storage` and `s3_storage` the command makes one
request per file and can take hours: run it as a Kubernetes Job instead of with
`kubectl exec`. A document that is not in the report is fine, apart from a few
cases the command cannot detect. Open Zaak's documentation, "Overwritten
documents" in the installation reference, explains each check and those cases.

### The worker's liveness ConfigMap

With `worker.livenessProbe.enabled: true` (podiumd's default), Open Zaak charts
1.15.0 and 1.16.0 give the worker a volume from ConfigMap
`openzaak-celery-liveness`, and no template creates it. Without it the worker
pod does not start. The volume is not mounted: the probe runs
`/celery_worker_liveness_probe.sh` from the image. podiumd therefore creates an
empty ConfigMap of that name in its own template,
`templates/openzaak-celery-liveness-configmap.yaml`, while `openzaak` and its
worker liveness probe are enabled.

## Reference: Open Klant 2.19

- **No `nummer` (2.16.0):** `InterneTaak.nummer`, `Klantcontact.nummer` and
  `Partij.nummer` are deprecated and no longer generated. New
  `referentienummer` fields on interne taak and klantcontact hold a client's
  own reference.
- **Image and chart (2.19.2 on chart 1.14.2):** the chart is built for 2.18.1.
  The 2.19 releases add no setting or environment variable; 2.19.0's migration
  crashes and is fixed in 2.19.1.
- **`UWSGI_PORT` is now `OPENKLANT_PORT` (2.18.0):** Kubernetes would inject
  `OPENKLANT_PORT=tcp://<ip>:80` for the `openklant` Service, as for Open Zaak
  (open-zaak#2415); chart 1.14.2 sets `enableServiceLinks: false` on the web
  pod, so nothing is injected.
- **Optional cleanup (2.19.0):** the temporary management command
  `delete_klantcontacten_not_related_to_zaken` deletes klantcontacten without
  a zaak. Run it only on request of the gemeente.
