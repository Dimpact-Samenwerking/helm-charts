# Frank!Gateway instances — PodiumD 4.8.3 → 4.8.4

**No gemeente `podiumd.yml` changes are required for this hop.** Frank!Gateway
gains a per-traffic-class instance model, but the default renders exactly the
manifests 4.8.3 did — verified by diffing a full `helm template` of both
versions. Environments that do not opt in are unaffected, including those that
already run Frank!Gateway.

## What changed

`frankgateway` now has an `instances` map. Everything outside the map stays the
shared default; each instance deep-merges its own overrides over it.

The key `gateway` is the reserved single-instance default: it keeps the bare
object names (`frankgateway`, `frankgateway-admin-credentials`,
`frankgateway-apisix-config`, `frankgateway-dashboard`, …) and the `/apisix`
etcd prefix. It is enabled by default, so doing nothing keeps today's behaviour.

New values, all off by default:

| Value | Purpose |
|---|---|
| `frankgateway.instances` | The instance map. Default: `gateway` only. |
| `frankgateway.serviceAlias` | Keeps the `frankgateway` Service name pointing at a chosen split instance during migration. |
| `frankgateway.networkPolicies` | Per-class NetworkPolicies (the first in this chart). |
| `<instance>.etcdPrefix`, `.nameOverride`, `.class`, `.routes.dirs` | Per-instance placement and routing. |

Route JSONs moved from `files/frankgateway/routes/*.json` into per-class
directories `routes/outway/` (BAG + the three KVK routes) and `routes/internal/`
(BRP). The default instance seeds both, so the same five routes are applied with
the same ids as before.

## If you opt into the split

See
[`../apps/frankgateway/frankgateway-traffic-classes.md`](../apps/frankgateway/frankgateway-traffic-classes.md)
for the full picture. Two things to plan for:

1. **The Admin API Secret is renamed per instance** —
   `frankgateway-<instance>-admin-credentials`. Any deployment pipeline that
   reads `frankgateway-admin-credentials` **by name** must be updated. jim00's
   `apply-routes.sh` does exactly this. Keep the `gateway` instance (or
   `nameOverride`) until the pipeline is ready.
2. **Consumers must be repointed** from `frankgateway:9080` to
   `frankgateway-outway:9080` or `frankgateway-internal:9080`. Enable
   `serviceAlias` so the old name keeps resolving and applications can move one
   at a time.

Each split instance also needs its own dashboard hostname
(`<instance>.dashboard.auth.hostname`), which means its own Keycloak client
(seeded by the chart) and its own entry in the gateway certificate SANs and DNS
(deploy-side). Set `dashboard.enabled: false` on classes that do not need a GUI.

NetworkPolicies are opt-in and only apply to instances with a `class` of
`inway`, `outway` or `internal`. A cluster whose CNI does not enforce
NetworkPolicy will accept and silently ignore them — enabling the value is not
evidence that traffic is restricted; verify on the target cluster.
