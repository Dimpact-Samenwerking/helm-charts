# Operators & CRDs — PodiumD 4.8.5 → 4.9.0

Companion to [`4.8.5-to-4.9.0-upgrade.md`](4.8.5-to-4.9.0-upgrade.md).

| Component | Change | CRD impact | Action |
|---|---|---|---|
| eck-operator | `3.4.0` → `3.5.0` (chart version and image both — image tag floats on the chart's `appVersion`, no override in `values.yaml`) | CRD schema change, **additive-only** (verified by diffing `charts/eck-operator-crds/templates/all-crds.yaml` between the two chart releases: 28 fields added, 0 removed) | None beyond the usual `helm upgrade` — no pre-upgrade adoption step needed, unlike the 4.8.0 introduction of eck-operator |
| eck-stack (kiss-eck) | chart `0.19.0` → `0.20.0` | None — eck-stack has no CRDs of its own, it only configures CRs of the eck-operator-owned kinds | None |

| redis-operator | chart `0.25.0` → `0.26.1`; operator image `v0.25.0` → `v0.26.0` (main + init-container, both now digest-pinned) | **None** — CRD diff between chart `0.25.0` and `0.26.1` is zero, byte-for-byte identical `crds/crds.yaml` (`diff` shows no output) | None beyond the usual `helm upgrade` |

## ECK Operator CRD diff — verification method

The additive-only claim was verified directly rather than taken from the
chart's release notes:

```bash
helm pull elastic/eck-operator --version 3.4.0 -d /tmp/eck-old && tar -xzf /tmp/eck-old/eck-operator-3.4.0.tgz -C /tmp/eck-old
helm pull elastic/eck-operator --version 3.5.0 -d /tmp/eck-new && tar -xzf /tmp/eck-new/eck-operator-3.5.0.tgz -C /tmp/eck-new
diff /tmp/eck-old/eck-operator/charts/eck-operator-crds/templates/all-crds.yaml \
     /tmp/eck-new/eck-operator/charts/eck-operator-crds/templates/all-crds.yaml
```

The diff is almost entirely reformatted description/comment text (upstream
regenerates the CRD doc-strings on every release). Filtering the diff down to
top-level property keys (`^\s*[a-zA-Z_-]+:\s*$` lines) shows 28 new keys added
and zero removed — no existing field was renamed, retyped, or dropped.

- ACR mirror: `elastic/eck-operator:3.5.0`
  ([`images-4.9.0.yaml`](../images/images-4.9.0.yaml)).

## redis-operator CRD diff — verification method

```bash
helm pull opstree/redis-operator --version 0.25.0 -d /tmp/redis-old && tar -xzf /tmp/redis-old/redis-operator-0.25.0.tgz -C /tmp/redis-old
helm pull opstree/redis-operator --version 0.26.1 -d /tmp/redis-new && tar -xzf /tmp/redis-new/redis-operator-0.26.1.tgz -C /tmp/redis-new
diff /tmp/redis-old/redis-operator/crds/crds.yaml /tmp/redis-new/redis-operator/crds/crds.yaml
```

Zero output — the two `crds.yaml` files are byte-for-byte identical. The only
`values.yaml` shape change between the two chart versions is `featureGates`
moving from a fixed map (`GenerateConfigInInitContainer: false`) to `{}` with
commented examples; our explicit
`redis-operator.featureGates.GenerateConfigInInitContainer: true` override is
still a supported gate per the (unchanged) CRD comments and needs no change.

- ACR mirror: `opstree/redis-operator:v0.26.0`, `opstree/redis:v8.6.6`,
  `opstree/redis-exporter:v1.89.0`
  ([`images-4.9.0.yaml`](../images/images-4.9.0.yaml)).
