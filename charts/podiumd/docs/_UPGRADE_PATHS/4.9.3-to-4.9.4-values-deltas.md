# Values deltas — PodiumD 4.9.3 → 4.9.4

**No gemeente `podiumd.yml` changes are required for this hop**, unless the
environment overrides one of the keys below.

## openinwoner 2.4.3 → 2.4.6 (chart 2.4.0, unchanged)

No keys were added, removed or renamed. One default changed:

- `openinwoner.settings.cms4MigrationInitContainer` now defaults to `false`.
  **Per-environment values must not set it to `true`**, or Open Inwoner does
  not start: the init container's `cms4_migration` command crashes from 2.4.5 on
  (`FieldError: Unsupported lookup 'node__site_id'`) and blocks the web pod.
  Remove an explicit `true` from the gemeente's values before deploying.
  Check with:

  ```bash
  grep -rn 'cms4MigrationInitContainer' <SSCHostingSync>/applications/gemeenten/
  ```

  No SSC environment set it at SSCHostingSync `539b0c1` (2026-10-07).

An environment that pins `openinwoner.image.tag` in its own values must move
that pin to `2.4.6` (digest in [`images-4.9.4.yaml`](../images/images-4.9.4.yaml)). An environment
that overrides `openinwoner.image.repository` must make sure 2.4.6 is in that
repository. No SSC environment pins the tag. Two
SSC environments use the old mirror name `acrprodmgmt.azurecr.io/openinwoner`; see
[`4.9.3-to-4.9.4-gemeente-specific.md`](4.9.3-to-4.9.4-gemeente-specific.md).
