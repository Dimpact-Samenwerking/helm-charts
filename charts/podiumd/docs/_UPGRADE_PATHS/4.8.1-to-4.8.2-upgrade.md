# Upgrade guide: PodiumD 4.8.1 → 4.8.2

> See the Confluence Releases page for the agreed application
> targets: <https://dimpact.atlassian.net/wiki/spaces/PCP/pages/7602191/Releases+PodiumD>.

This is the upgrade guide for environments already on **4.8.1** (the current
stable baseline).

### Shared image consolidation: nginx-unprivileged, curl, busybox

Every `nginx-unprivileged`, `curlimages/curl` and `busybox` pin in
`values.yaml` now comes from one shared `global.images.<name>` YAML anchor per
image, instead of each component repeating its own `repository`/`tag`.

The consolidation carried three real changes:

- **nginx-unprivileged: `1.31.1` → `1.31.3`** — everywhere it is pinned:
  `zac.nginx`, `apiproxy`, and the nginx sidecars of `openzaak`,
  `openarchiefbeheer`, `openklant`, `openformulieren`, `openinwoner` and
  `openbeheer`. Also covers the Frank!Gateway dashboard-auth shim, which was
  previously on the unrelated, undigested `1.27-alpine`.
- **curl: `8.20.0` → `8.21.0`** — everywhere it is pinned:
  `keycloak-operator.jobs.ensureOperatorSa`, `zac.global.curlImage`, and the
  Frank!Gateway routes-seeding job (previously undigested).
- **busybox: no version change** (still `1.38.0-glibc`; confirmed current — no
  newer versioned glibc tag exists upstream). The redis-ha init-container's
  repository path changed from bare `busybox` to `library/busybox` to match
  `images-baseline.yaml`'s actual mirror name. Same upstream image; this
  corrects a latent ACR-mirror-path mismatch for environments that don't
  override this field.

**No `podiumd.yml` edit is needed for any of this:**

- Every gemeente `podiumd.yml` in `ExternalsPodiumD` was checked: all override
  `registry`/`repository` for these images (their own ACR mirror) but never
  `tag` — so every environment inherits the new tags from the chart defaults
  automatically.
- The only action is the ACR mirror step in the checklist below; the new
  nginx-unprivileged and curl digests are already in
  [`images-4.8.2.yaml`](../images/images-4.8.2.yaml).
- One known exception — a gemeente that pins `nginx-unprivileged`'s tag
  directly and is therefore unaffected by this bump either way — is documented
  in [`4.8.1-to-4.8.2-gemeente-specific.md`](4.8.1-to-4.8.2-gemeente-specific.md).

### Realm-import jobs now use the in-cluster Keycloak URL

**Problem (4.8.1 and earlier):** the `import-master-realm-job` /
`import-podiumd-realm-job-*` jobs (keycloak-config-cli) resolved
`KEYCLOAK_URL` from `keycloak.hostname.admin` /
`keycloak.config.adminFrontendUrl` — the *public* admin host. On environments
where that host sits behind a gateway IP-allowlist (e.g. a `SnippetsFilter`
with `deny all`), the in-cluster job traffic egresses via the cluster's NAT IP
and is rejected with an nginx `403 Forbidden` at token grant, leaving the
import jobs in a retry loop. First seen on ontw-dimp.

**Fix (4.8.2):** the jobs default to `http://keycloak-service:8080`
(in-cluster).

- No values change needed.
- Override with `keycloak-operator.jobs.keycloakUrl` only if the jobs must
  reach Keycloak via another URL.

## Per-environment checklist

Read the whole guide once first. Then, for **every environment** you upgrade,
work through this list top to bottom. Each item links to the full instructions
above; the gemeente-values edits (phase B) are detailed key-by-key in
[`4.8.1-to-4.8.2-values-deltas.md`](4.8.1-to-4.8.2-values-deltas.md).

### A. Prepare

- [ ] **ACR mirror**: mirror the 4.8.2 image set under the
      strip-registry names ([`images-4.8.2.yaml`](../images/images-4.8.2.yaml))

### B. Deploy

- [ ] Run the deploy pipeline / `helm upgrade`.
