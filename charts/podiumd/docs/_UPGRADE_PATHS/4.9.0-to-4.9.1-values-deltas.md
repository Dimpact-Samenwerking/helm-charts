# Values deltas — PodiumD 4.9.0 → 4.9.1

**No gemeente `podiumd.yml` changes are required for this hop**, except for
gemeentes hitting the FTP EPSV issue below (currently: Assen — see
[`4.9.0-to-4.9.1-gemeente-specific.md`](4.9.0-to-4.9.1-gemeente-specific.md))
and for environments that run **Frank!Gateway** (`frankgateway.enabled: true`
— none of the gemeenten today), whose route keys move, see below.

## Breaking — Frank!Gateway routes (only when `frankgateway.enabled: true`)

The chart no longer ships any route, and the values keys moved:

| 4.9.0 | 4.9.1 |
| --- | --- |
| `frankgateway.instances.<class>.routes.extra.<id>` | `frankgateway.instances.<class>.routes.<id>` |
| `frankgateway.routes.seed` | `frankgateway.seed.enabled` |
| `frankgateway.routes.job.*` | `frankgateway.seed.job.*` |
| chart-shipped BAG, KVK×3, BRP route files | gone — copy the bodies from [`frankgateway-routes.md`](../apps/frankgateway/frankgateway-routes.md) into your values |

The render fails, naming the key, while the old ones are still set. New
optional `frankgateway.seed.prune` (default `false`) deletes `managed-by: iac`
routes that are not in the render. The hook objects were renamed
(`-apply-routes`/`-routes` → `-seed`); delete the orphaned ConfigMaps once:
`kubectl -n podiumd delete configmap -l app.kubernetes.io/component=frankgateway-routes`.

## New optional key

- **`mi.transfer.noEpsv`** (default `false`, mi-data chart 1.0.0 → 1.1.0,
  [IN-2812](https://dimpact.atlassian.net/browse/IN-2812)) — ftp transfer
  mode only. Set `true` to add `curl --no-epsv`, forcing classic PASV for
  the data connection, for FTP servers/NAT paths that mishandle EPSV
  (RFC 2428). No action needed unless an environment's ftp upload hangs or
  times out opening the data connection — see the mi-data chart's
  [troubleshooting table](../../../mi-data/docs/mi-exports.md#troubleshooting).

## No action needed (informational)

- **Keycloak Operator**: `keycloak-operator.operator.image.sha` was added —
  this is podiumd's own chart-default override, not a gemeente-facing key.
  It pins the Keycloak Operator image digest explicitly because the adfinis
  1.13.0 chart's bundled default `operator.image.sha` doesn't match any
  manifest published under the `26.7.3` tag (it doesn't know that tag
  exists — no chart has been cut for it yet). See
  [`4.9.0-to-4.9.1-upgrade.md`](4.9.0-to-4.9.1-upgrade.md) for the full
  double-digest caveat this works around.
- Keycloak server + operator image tags moved to `26.7.3` (the operator
  image specifically moved `26.6.4` → `26.7.3`, completing a pin that was
  left inconsistent in 4.9.0); these are podiumd chart defaults, not values
  a gemeente `podiumd.yml` overrides.
