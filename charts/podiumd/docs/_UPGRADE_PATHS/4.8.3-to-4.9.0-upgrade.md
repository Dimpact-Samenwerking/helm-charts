# Upgrade guide: PodiumD 4.8.2 → 4.9.0

> See the Confluence Releases page for the agreed application
> targets: <https://dimpact.atlassian.net/wiki/spaces/PCP/pages/7602191/Releases+PodiumD>.

This is the upgrade guide for environments already on **4.8.2** (the current
stable baseline).

## Component versions (4.9.0 vs 4.8.2)

| Component | App version | Helm chart | Notes |
| --- | --- | --- | --- |
| ZAC (Zaakafhandelcomponent) | 5.0.1 → 5.1.0 | 1.0.251 → 1.0.257 | ACR mirror only — see note below |
| ZGW Office Add-in (frontend + backend) | v0.9.313 → v0.9.352 | 0.0.89 (unchanged) | ACR mirror only — see note below |
| KISS | 2.2.4 → 3.0.0 | 2.2.4 → 3.0.0 | **action required** — Enterprise Search removed, `podiumd.yml` edits needed |

## Changes

### ZAC 5.0.1 → 5.1.0 (chart 1.0.251 → 1.0.257)

PodiumD 4.9.0 upgrades **ZAC (Zaakafhandelcomponent)** from app version 5.0.1
to 5.1.0.

- Helm chart `zaakafhandelcomponent` `1.0.251` → `1.0.257` in
  `charts/podiumd/Chart.yaml`.
- Image tag pin `zac.image.tag` `5.0.1` → `5.1.0` in
  `charts/podiumd/values.yaml`.
- Image / digest: see [`images-4.9.0.yaml`](../images/images-4.9.0.yaml).

**No `podiumd.yml` action required.** The only chart-level change is the ZAC
image tag, which every environment inherits from the chart default (gemeente
`podiumd.yml` files override `registry`/`repository` for their own ACR mirror
but never `tag`). The ZAC sidecar images (nginx-unprivileged, curl, busybox,
gotenberg, opa) are unchanged from 4.8.2.

> The ZAC 5.0.1 `brpApi.apiKey` / `protocollering` structured configuration
> was introduced in the **4.8.1 → 4.8.2** hop — see
> [`4.8.1-to-4.8.2-gemeente-specific.md`](4.8.1-to-4.8.2-gemeente-specific.md#zac--brp-protocollering-configuration-per-gemeente).
> It is unchanged in 5.1.0; nothing to redo here. For application-level
> behaviour changes between ZAC 5.0.1 and 5.1.0, see the ZAC release notes.

### ZGW Office Add-in v0.9.313 → v0.9.352 (chart 0.0.89, unchanged)

PodiumD 4.9.0 upgrades the **ZGW Office Add-in** frontend and backend from
`v0.9.313` to `v0.9.352`. The Helm chart version remains `0.0.89`.

- Image tag pins `zgw-office-addin.frontend.image.tag` and
  `zgw-office-addin.backend.image.tag` updated in
  `charts/podiumd/values.yaml`.
- Image / digests: see [`images-4.9.0.yaml`](../images/images-4.9.0.yaml).

**No `podiumd.yml` action required.** As with ZAC, the tags come from the chart
defaults; environments only override `registry`/`repository`. The repository
names (`zgw-office-addin-{frontend,backend}`, hyphen already dropped) are
unchanged from 4.8.2.

### KISS 2.2.4 → 3.0.0 — Enterprise Search removed

KISS 3.0.0 no longer uses Enterprise Search. It queries the Elasticsearch
`search-*` indices directly, and websites are crawled by the **Elastic Open
Crawler**, which runs as a CronJob per site and writes straight to
Elasticsearch. A `pre-install`/`pre-upgrade` hook (`crawler-index-template`)
registers the `kiss-crawler-website` index template first.

There is **no migration path** and no data migration: existing indices, the
Elasticsearch StatefulSet and its PVCs are untouched. Enterprise Search may be
left running; KISS simply stops using it. See the
[KISS changelog](https://github.com/Klantinteractie-Servicesysteem/KISS-frontend/blob/main/docs/changelog/changelog.md).

Verified on test00 (podiumd 4.8.0 → this branch): StatefulSet UID and all three
PVCs unchanged, index template registered, crawler CronJob completed without
errors.

**Three things bite in practice. All three were hit on test00:**

1. **`settings.syncJobs.website.domain` must not contain a path, not even a trailing slash.** The Open
   Crawler rejects it where the Enterprise Search crawler accepted it:

   ```
   ArgumentError: Domain "https://www.example.nl/" cannot have a path
   ```

   Strip the trailing slash from every `kiss.settings.syncJobs.website[].domain`
   in `podiumd.yml`. The CronJob crashloops otherwise; the deploy itself stays
   green, so this is easy to miss.

2. **The Elasticsearch password must be correct before you upgrade.** The
   index-template hook runs `pre-upgrade` and fails the whole release on a bad
   credential:

   ```
   curl: (22) The requested URL returned error: 401
   Error: UPGRADE FAILED: pre-upgrade hooks failed: resource Job/podiumd/contact-crawler-index-template not ready
   ```

   `kiss.settings.elastic.password` must match the ECK-generated password in
   Secret `kiss-es-elastic-user`. Until 3.0.0 a stale value only broke the sync
   jobs silently (crashlooping jobs, `search-*` indices at 0 documents); now it
   blocks the deploy. Check before upgrading:

   ```bash
   PW=$(kubectl get secret -n podiumd kiss-es-elastic-user -o go-template='{{.data.elastic|base64decode}}')
   printf 'user = "elastic:%s"\n' "$PW" | kubectl exec -i -n podiumd kiss-es-default-0 -c elasticsearch -- \
     curl -s -k -K - -o /dev/null -w '%{http_code}\n' "https://localhost:9200/_cat/health"
   ```

3. **Three images move.** `kiss-elastic-sync` follows the chart version
   (`0.3.3` → `3.0.0`).  `docker.elastic.co/integrations/crawler:1.0.0` is the 
   new image for the Elastic Open Crawler. And KISS uses Curl to create the 
   indexes for Websites, so this image is also part of the KISS values.
   The kiss chart does **not** honour `global.imageRegistry`, so
   environments that pin `kiss.image.repository` to the ACR mirror must also
   pin `syncJobs.crawlerImage.repository` and
   `syncJobs.indexTemplateImage.repository`, or Azure Policy blocks the pods.

**`podiumd.yml` action required:** remove the `kiss.settings.enterpriseSearch`
block (`baseUrl`, `engine`, `publicApiKey`, `privateApiKey`). The keys no
longer exist in the subchart. The matching key vault secrets become unused.

## Per-environment checklist

Read the whole guide once first. Then, for **every environment** you upgrade,
work through this list top to bottom. Gemeente-values edits: see
[`4.8.2-to-4.9.0-values-deltas.md`](4.8.2-to-4.9.0-values-deltas.md).

### A. Prepare

- [ ] **ACR mirror**: mirror the 4.9.0 image set under the strip-registry
      names ([`images-4.9.0.yaml`](../images/images-4.9.0.yaml)) — ZAC `5.1.0`,
      ZGW Office Add-in `v0.9.352` frontend/backend, KISS `3.0.0`,
      `kiss-elastic-sync` `3.0.0` and the new `integrations/crawler` `1.0.0`.
- [ ] **Check the Elasticsearch password** against `kiss-es-elastic-user`
      (command above). A stale value fails the deploy on the pre-upgrade hook.

### B. Edit the gemeente `podiumd.yml`

- [ ] Remove the `kiss.settings.enterpriseSearch` block.
- [ ] Strip trailing slashes from every `syncJobs.website[].domain`.
- [ ] ACR-mirrored environments: pin `syncJobs.crawlerImage.repository` and
      `syncJobs.indexTemplateImage.repository`.

### C. Deploy

- [ ] Run the deploy pipeline / `helm upgrade`.

### D. Verify

- [ ] Elasticsearch StatefulSet UID and PVCs unchanged.
- [ ] Index template `kiss-crawler-website` present
      (`GET _cat/templates`).
- [ ] Crawler CronJob `contact-crawler-website-<n>` runs to `Completed`, not
      `CrashLoopBackOff`.
