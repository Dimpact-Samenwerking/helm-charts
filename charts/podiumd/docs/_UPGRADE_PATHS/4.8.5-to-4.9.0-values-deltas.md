# Values deltas — PodiumD 4.8.5 → 4.9.0

## KISS 2.2.4 → 3.0.0 — required edits

**KISS 3.0.0 requires gemeente `podiumd.yml` edits — see below.** ITA 3.3.0 needs
an edit only if you override `ita.poller.schedule`/`ita.poller.notification`
(see [ITA below](#ita-320--330--poller-split)). Every other change ships
entirely in the chart `values.yaml`/`Chart.yaml` defaults.

Background and failure modes in
[`4.8.5-to-4.9.0-upgrade.md`](4.8.5-to-4.9.0-upgrade.md).

### 1. Remove `kiss.settings.enterpriseSearch` (required)

```yaml
kiss:
  settings:
    enterpriseSearch:          # <- remove the whole block
      baseUrl: "..."
      engine: "kiss-engine"
      publicApiKey: "..."
      privateApiKey: "..."
```

The keys no longer exist in the subchart. The matching key vault secrets
(`ENTERPRISE_SEARCH_PUBLIC_API_KEY`, `ENTERPRISE_SEARCH_PRIVATE_API_KEY`)
become unused.

### 2. Strip trailing slashes from crawler domains (required where present)

The Elastic Open Crawler rejects a domain with a path, including a bare
trailing slash, where the Enterprise Search crawler accepted it. The deploy
stays green; only the CronJob crashloops.

```yaml
kiss:
  settings:
    syncJobs:
      website:
        - sourceName: "info"
          domain: "https://www.info.nl"   # was https://www.info.nl/
```

### 3. Pin the two new image repositories (ACR-mirrored environments)

The kiss chart does not honour `global.imageRegistry`. Environments that
already pin `kiss.image.repository` and `syncJobs.image.repository` to the
mirror must add:

```yaml
kiss:
  settings:
    syncJobs:
      crawlerImage:
        repository: acrprodmgmt.azurecr.io/integrations/crawler
      indexTemplateImage:
        repository: acrprodmgmt.azurecr.io/curlimages/curl
```

### Not a values change, but check it first

`kiss.settings.elastic.password` must match the ECK-generated password in
Secret `kiss-es-elastic-user`. From 3.0.0 a stale value fails the deploy on the
`crawler-index-template` pre-upgrade hook.

## ITA 3.2.0 → 3.3.0 — poller split

In 3.3.0 the single `poller` CronJob is split into two. Environments that
customise the poller schedule or notification must migrate their overrides.
Note: the value `poller.notification.hourThreshold` has been removed from the chart

### Migrate `ita.poller` overrides to `ita.nieuweInternetaakNotificatie` (required if customised)

```yaml
# Before (3.2.0)
ita:
  poller:
    schedule: "*/10 * * * *"
    notification:
      pollerMessage: "Poller uitgevoerd om:"
      hourThreshold: "-24"
```

```yaml
# After (3.3.0)
ita:
  nieuweInternetaakNotificatie:
    schedule: "*/10 * * * *"
    notification:
      pollerMessage: "Poller uitgevoerd om:"
```

The new `verlopenContactverzoekHerinneringNotificatie` CronJob (daily reminder
for expired contact requests, weekdays 07:00) is enabled by default — no action
needed unless you want to disable or reschedule it.

If your environment does not override `ita.poller.schedule` or
`ita.poller.notification`, no `podiumd.yml` changes are needed.
