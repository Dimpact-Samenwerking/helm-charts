## Before you deploy (every environment)

- Give Open Archiefbeheer's Objecten token `read_and_write` on the
  productaanvraag object type, so destroying a zaak can delete its related
  objects in Objecten (IN-2784). Run
  `scripts/migrate-objecten-openarchiefbeheer-permissions-4.10.1.py` with
  `--dry-run` first, then without, on the gemeente `podiumd.yml` files: see
  [Open Archiefbeheer cannot delete objects in Objecten](4.10.0-to-4.10.1-gemeente-specific.md#all-environments-open-archiefbeheer-cannot-delete-objects-in-objecten-in-2784).
  Environments that go from 4.9.6 straight to 4.10.1 need the same step.

## Open Archiefbeheer logs to stdout (IN-3284)

- **Application logs move from a file to stdout.** The podiumd chart now sets
  `openarchiefbeheer.settings.logging.toStdout: true` (with `level: INFO`).
  The openarchiefbeheer chart writes `LOG_STDOUT=False` unless this is set,
  so OAB logged to a file in the container, which Grafana does not collect.
  After the upgrade the OAB logs, such as destruction list processing and
  OIDC login errors, show in Grafana.
- **Celery worker and beat log at `info` instead of `warning`.**
  `openarchiefbeheer.settings.celery.logLevel` goes from `warning` to `info`.
  On `warning` beat logs only its startup banner and the worker a few lines
  a day, so they hardly showed in the Grafana Logs dashboard.
- **More log volume in Loki.** Both changes increase the number of OAB log
  lines.
- An environment that sets `openarchiefbeheer.settings.logging` or
  `openarchiefbeheer.settings.celery.logLevel` in its `podiumd.yml` keeps its
  own value. No SSC environment sets them today.

## Keycloak public hostname for fresh installs (IN-3281)

- **New value, off by default: `keycloak.hostname.useRealmFrontendUrl`.**
  When `keycloak.hostname.hostname` is empty, it makes Keycloak's public
  hostname fall back to `keycloak.config.realmFrontendUrl` instead of
  `keycloak.config.adminFrontendUrl`. It is meant for fresh installs, where
  the admin host as public hostname makes logins fail until the realm import
  has run (see `docs/apps/keycloak/keycloak-BASICS.md`).
- **No action for existing environments.** With the default, the rendered
  Keycloak CR is the same as in 4.10.0, and Keycloak does not restart.
- **Turning it on** where `realmFrontendUrl` differs from `adminFrontendUrl`
  moves the public hostname to the realm host and restarts Keycloak. Admin
  console and admin REST URLs stay on `keycloak.hostname.admin`; the admin
  console login stays on the admin host only while the `import-master-realm`
  Job runs, which needs `keycloak-operator.jobs.ensureOperatorSa.clientSecret`.
