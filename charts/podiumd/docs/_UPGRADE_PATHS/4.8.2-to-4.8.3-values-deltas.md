# Values deltas — PodiumD 4.8.2 → 4.8.3

**Environments with `mi.enabled: false` (the default) need no gemeente
`podiumd.yml` changes for this hop.**

## MI exports enabled: migrate `mi.sftp.*` → `mi.transfer.*` (BREAKING)

The MI export tooling moved to the standalone `mi-data` subchart and the
transfer configuration became one unified section with an explicit mode.
Rendering with un-migrated values fails fast with
`transfer.mode must be one of: sftp-password, sftp-key, ftp` — the deploy
cannot silently proceed with old keys.

Key-by-key:

| Action | Key | Notes |
| --- | --- | --- |
| **add** | `mi.transfer.mode` | `sftp-password` (had `mi.sftp.password`), `sftp-key` (had `mi.sftp.privateKey`), or `ftp` (new) |
| **rename** | `mi.sftp.host` → `mi.transfer.host` | value unchanged |
| **rename** | `mi.sftp.port` → `mi.transfer.port` | value unchanged; empty → 22 (sftp modes) / 21 (ftp) |
| **rename** | `mi.sftp.user` → `mi.transfer.user` | value unchanged |
| **rename** | `mi.sftp.remotePath` → `mi.transfer.remotePath` | value unchanged for the sftp modes; ftp mode is home-relative (`//abs/path` forces absolute) |
| **rename** | `mi.sftp.password` → `mi.transfer.password` | keep the `REP_MI_DATA_SFTP_CREDENTIAL_REP` placeholder |
| **rename** | `mi.sftp.privateKey` → `mi.transfer.privateKey` | keep the placeholder |
| **remove** | `mi.sftp` | the whole block — no `mi.sftp.*` key survives |
| optional | `mi.transfer.ftps: true` | ftp mode only: explicit TLS (FTPS) — strongly preferred over plain FTP |

Example (sftp-password environment):

```yaml
# 4.8.2                                   # 4.8.3
mi:                                       mi:
  enabled: true                             enabled: true
  gemeente: jim00                           gemeente: jim00
  sftp:                                     transfer:
    host: x.blob.core.windows.net             mode: sftp-password
    user: x.miuser                            host: x.blob.core.windows.net
    remotePath: /mi-exports                   user: x.miuser
    password: "REP_MI_DATA_SFTP_…_REP"        remotePath: /mi-exports
                                              password: "REP_MI_DATA_SFTP_…_REP"
```

**ExternalsPodiumD pipeline:** the Key Vault substitution target moves from
`mi.sftp.password` / `mi.sftp.privateKey` to `mi.transfer.password` /
`mi.transfer.privateKey`; the KV secret name (`mi-data-sftp-credential`) is
unchanged. Optionally trim `mi.targets` to the components actually deployed —
un-trimmed targets now render CronJobs that run as weekly no-ops (see the
[upgrade guide](4.8.2-to-4.8.3-upgrade.md#other-mi-changes-at-this-hop)).

## Frank!Gateway TLS listener (opt-in, no default action)

| Action | Key | Notes |
| --- | --- | --- |
| optional | `frankgateway.tls.enabled: true` | only for environments behind a re-encrypting front door (Gateway API `BackendTLSPolicy`); default `false` renders identically to 4.8.2 |
| optional | `frankgateway.tls.port` | https data-plane port, default `9443` |

Per-SNI server certificates are seeded deploy-side via the APISIX Admin API
(SSL objects in etcd) — nothing is mounted by the chart. See the
[upgrade guide](4.8.2-to-4.8.3-upgrade.md#frankgateway-optional-tls-listener-on-the-data-plane-394).
