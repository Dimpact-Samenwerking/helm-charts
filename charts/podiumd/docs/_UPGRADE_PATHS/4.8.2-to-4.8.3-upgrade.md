## MI exports: extracted to the `mi-data` subchart (IN-2499)

The MI export tooling moved out of the podiumd chart into the standalone
[`mi-data` chart](../../../mi-data/) (this repo, released independently as
`mi-data-<version>`). podiumd 4.8.3 consumes it as an optional dependency
under **alias `mi`** with `condition: mi.enabled` — the top-level `mi.*`
values prefix is unchanged.

**No action** for environments with `mi.enabled: false` (the default).

### BREAKING: `mi.sftp.*` → unified `mi.transfer.*`

Transfer configuration is now one unified section with an explicit mode.
Environments with MI exports enabled **must migrate their values file** at
this upgrade — rendering with un-migrated values fails fast with
`transfer.mode must be one of: sftp-password, sftp-key, ftp`.

| 4.8.2 (old) | 4.8.3 (new) |
| --- | --- |
| `mi.sftp.host` / `port` / `user` / `remotePath` | `mi.transfer.host` / `port` / `user` / `remotePath` (unchanged meaning; `port` empty → 22 for the sftp modes, 21 for ftp) |
| `mi.sftp.password: <pw>` | `mi.transfer.mode: sftp-password` **+** `mi.transfer.password: <pw>` |
| `mi.sftp.privateKey: <pem>` | `mi.transfer.mode: sftp-key` **+** `mi.transfer.privateKey: <pem>` |
| — | **new:** `mi.transfer.mode: ftp` + `mi.transfer.password` (classic FTP via curl); add `mi.transfer.ftps: true` for explicit TLS (FTPS) — strongly preferred, plain FTP is cleartext |

Example migration (sftp-password):

```yaml
# 4.8.2                                   # 4.8.3
mi:                                       mi:
  enabled: true                             enabled: true
  gemeente: jim00                           gemeente: jim00
  sftp:                                     transfer:
    host: x.blob.core.windows.net             mode: sftp-password
    user: x.miuser                            host: x.blob.core.windows.net
    remotePath: /mi-exports                   user: x.miuser
    password: "REP_MI_DATA_SFTP_…_REP"        remotePath: /mi-exports
                                              password: "REP_MI_DATA_SFTP_…_REP"
```

**ExternalsPodiumD pipeline:** the Key Vault substitution target moves from
`mi.sftp.privateKey` / `mi.sftp.password` to `mi.transfer.privateKey` /
`mi.transfer.password`. The KV secret name (`mi-data-sftp-credential`) is
unchanged.

### Other MI changes at this hop

- **Secrets renamed** (automatic, same Helm release — no manual action):
  `mi-export-sftp` → `mi-export-transfer`, `mi-export-sftp-key` →
  `mi-export-transfer-key`. The upgrade deletes the old Secrets and creates
  the new ones in one apply.
- **Per-target gating changed:** the subchart cannot see the umbrella chart's
  `<component>.enabled` flags, so a CronJob now renders for **every** entry
  in `mi.targets[]`. Targets for undeployed components run as weekly no-ops
  (the job logs `skip: …` and exits 0). Trim `mi.targets` in the env values
  to the components actually deployed if the no-op runs are unwanted.
- **Labels:** MI resources now carry `helm.sh/chart: mi-data-<version>` /
  `app.kubernetes.io/name: mi-data` instead of the podiumd equivalents —
  cosmetic; nothing selects on them.
- Operator guide moved:
  [`charts/mi-data/docs/mi-exports.md`](../../../mi-data/docs/mi-exports.md).

## Per-environment checklist

Read the whole guide once first. Then, for **every environment** you upgrade,
work through this list top to bottom. The gemeente-values edits (phase B) are
detailed key-by-key in
[`4.8.2-to-4.8.3-values-deltas.md`](4.8.2-to-4.8.3-values-deltas.md).

### A. Prepare

- [ ] **ACR mirror**: no new images for this hop so far — the MI export jobs
      keep using `mcr.microsoft.com/azure-cli:2.71.0`, already in
      [`images-baseline.yaml`](../images/images-baseline.yaml).

### B. Gemeente values (only when `mi.enabled: true`)

- [ ] Migrate the `mi.sftp.*` block to `mi.transfer.*` with an explicit
      `mode` ([values-deltas](4.8.2-to-4.8.3-values-deltas.md)).
- [ ] Move the deploy pipeline's Key Vault substitution target to
      `mi.transfer.password` / `mi.transfer.privateKey`.
- [ ] Optionally trim `mi.targets` to the components actually deployed.

### C. Deploy

- [ ] Run the deploy pipeline / `helm upgrade`.
- [ ] If MI is enabled: verify with
      `kubectl -n podiumd get cronjob -l app.kubernetes.io/component=mi-export`
      and check `Secret/mi-export-transfer` exists (the old
      `mi-export-sftp*` Secrets are removed by the upgrade).
