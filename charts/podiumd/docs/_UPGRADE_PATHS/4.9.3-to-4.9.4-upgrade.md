## Changes

### openinwoner 2.4.3 → 2.4.5 (chart 2.4.0, unchanged)

PodiumD 4.9.4 upgrades **openinwoner** from app version 2.4.3
to 2.4.5.

- Image tag pin `openinwoner.image.tag` `2.4.3` → `2.4.5` in
  `charts/podiumd/values.yaml`.

Both 2.4.4 and 2.4.5 are regular bugfix releases (per upstream
[compare v2.4.3...v2.4.5](https://github.com/maykinmedia/open-inwoner/compare/v2.4.3...v2.4.5)) —
no new database migrations, no new settings or environment variables, no
migration steps. Helm chart `openinwoner` stays at `2.4.0` in
`charts/podiumd/Chart.yaml`; only the app image tag moves.

Notable fixes:

- OpenTelemetry works again in the web pod: uWSGI no longer runs with
  `--lazy-apps` (2831), and each role exports its own `OTEL_SERVICE_NAME`
  (`openinwoner-web`, `-celery-worker`, `-celery-beat`, `-celery-monitor`)
  instead of the generic `openinwoner` (2832). This only matters for
  environments with the `values-enable-observability.yaml` overlay. Grafana
  dashboards or alerts that filter on `service.name="openinwoner"` must
  use the per-role names.
- Questions (vragen) are created and the vragen cache is invalidated even
  when creating the interne taak fails; registration failures are logged
  (2878).
- Non-standard digital address changes are pushed to OpenKlant (2852).
- Notifications skip opted-out users instead of aborting (2807).
- Better error handling in the ZGW and KIC `setup_configuration` steps
  (2594), zaken cache key fixes (2786), template-injection hardening of
  `RenderableTag` (2776), django-cms 5.0.11 and dependency security bumps.
