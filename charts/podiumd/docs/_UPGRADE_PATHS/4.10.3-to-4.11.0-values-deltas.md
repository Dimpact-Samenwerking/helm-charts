# Values deltas — PodiumD 4.10.3 → 4.11.0

What changes in a gemeente `podiumd.yml`, `services-gateway.yml` and
`ssl-gateway.yml` for this hop, and nothing else. Why, the pre- and
post-deploy steps and the rollback are in
[`4.10.3-to-4.11.0-upgrade.md`](4.10.3-to-4.11.0-upgrade.md).

## zac 5.9.1 → 5.13.0 (chart 1.0.355 → 1.0.409)

Only where ZAC sends its traces to the monitoring collector through
`zac.opentelemetry_zaakafhandelcomponent.endpoint` (ExternalsPodiumD
`09a9d10`: 6 of 8 environments, the `ontw` environments of dim2, dim3, dimp,
icat, info and mayk):

```yaml
zac:
  tracing:
    enabled: true                                   # new
    endpoint: "http://monitoring-opentelemetry-collector.monitoring.svc.cluster.local:4317"   # was opentelemetry_zaakafhandelcomponent.endpoint
  opentelemetry_zaakafhandelcomponent:              # remove
  opentelemetry-collector:                          # remove; enabled with replicaCount 0, it only turned tracing on
```

Recommended, not yet required: chart 1.0.409 still reads the old keys and
prints a deprecation notice for each; a later chart drops them.

## omc 2.3.1 → 2.4.1 (chart 0.17.4 → 0.17.8)

Only where OMC's Berichtenbox (MOBB) scenario is turned on: OMC then sends
the berichten Open VTB publishes. Elsewhere keep the chart defaults of
`omc.settings.zgw.auth.key.openvtb` and `omc.settings.zgw.endpoint.openVtb`.
The render fails while `endpoint.openVtb` is set and `endpoint.documenten` is
empty: OMC would send every bericht without its bijlagen.

```yaml
omc:
  settings:
    notify:
      templateId:
        email:
          messageBox: <Notify NL template id>   # e-mail when the bericht is in the Berichtenbox
        letter:
          messageBox: <Notify NL template id>   # letter fallback, optional
    zgw:
      auth:
        key:
          openvtb: REP_OMC_OPENVTB_KEY_REP      # an API key generated in Open VTB
      endpoint:
        openVtb: https://openvtb.<domain>/berichten/api/v1
        documenten: https://openzaak.<domain>/documenten/api/v1   # new key
      whitelist:
        vtbMessage:
          types: "*"                            # or a comma-separated list of berichttypen

openvtb:
  enabled: true
  celery:
    enabled: true                               # default; the worker and beat send the CloudEvents
  # An environment that sets its own extraEnvVars repeats these two.
  extraEnvVars:
    - name: OPENVTB_PORT
      value: "8000"
    - name: NOTIFICATIONS_SOURCE
      value: openvtb
  configuration:
    secrets:
      openvtb_opennotificaties_secret: REP_OPENVTB_OPENNOTIFICATIES_SECRET_REP   # new
    data: |-
      # Open VTB sends its CloudEvents to Open Notificaties as client openvtb.
      zgw_consumers_config_enable: true
      zgw_consumers:
        services:
          - identifier: notificaties-api
            label: Open Notificaties
            api_root: https://opennotificaties.<domain>/api/v1/
            api_type: nrc
            auth_type: zgw
            client_id: openvtb
            secret: {value_from: {env: openvtb_opennotificaties_secret}}
      notifications_config_enable: true
      notifications_config:
        notifications_api_service_identifier: notificaties-api
```

Client `openvtb` also needs:

- an Applicatie in the Autorisaties API of Open Zaak
  (`openzaak.configuration.data`, `vng_api_common_applicaties`) with
  `notificaties.publiceren`, or `heeft_alle_autorisaties: true`;
- its secret in Open Notificaties (`opennotificaties.configuration.data`,
  `vng_api_common_credentials`, identifier `openvtb`), the same secret as
  `openvtb_opennotificaties_secret` above.

Made by hand, not by values: a separate abonnement in Open Notificaties that
sends Open VTB's CloudEvents to OMC. Never turn on `sendCloudevents` on OMC's
existing `zaken` abonnement: Open Notificaties then sends the zaken
notifications as CloudEvents too, and OMC handles none of them.

- `callbackUrl`: `https://omc.<domain>/Events/Listen`
- `auth`: `Bearer <JWT>`, signed HS256 with `omc.settings.omc.auth.jwt.secret`
  and with its `issuer`, `audience`, `userId` and `userName` as claims, and an
  `exp`. OMC refuses an expired token, and Open Notificaties keeps the header
  as written: renew the abonnement's `auth` before `exp`, or OMC stops
  receiving berichten. For example one year, with a reminder to renew.
- `sendCloudevents: true`
- `cloudeventFilters: [{typeSubstring: "nl.overheid.berichten."}]`
