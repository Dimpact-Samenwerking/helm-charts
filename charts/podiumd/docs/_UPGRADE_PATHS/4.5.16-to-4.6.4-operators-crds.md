# Operators & CRDs — PodiumD 4.5.16 → 4.6.4

Companion to [`4.5.16-to-4.6.4-upgrade.md`](4.5.16-to-4.6.4-upgrade.md).

| Component | Change | CRD impact | Action |
|---|---|---|---|
| redis-operator (OT-Container-Kit) | **Introduced** (`v0.24.0`) — manages the shared `redis-ha` `RedisReplication` cluster | **New CRDs** installed by the chart (`RedisReplication`, sentinel-related kinds from the ot-helm chart) | Add the `redis-operator:` block to gemeente values (ACR envs also override the operator/exporter/init images) — see the guide |
| keycloak-operator | New `keycloak-operator.jobs` (incl. `ensureOperatorSa` provisioning the operator service-account client) | None | Set `ensureOperatorSa.clientSecret`; add `REP_KEYCLOAK_OPERATOR_SA_CLIENT_SECRET_REP` to the pipeline replacements |
| keycloak-operator RBAC | New `keycloak-operator-servicemonitor-rbac.yaml` template | None (RBAC on `monitoring.coreos.com`) | None — rendered automatically when `keycloak-operator.enabled: true`. Without it the operator gets HTTP 403 and aborts reconciliation |
| eck-operator (kisselastic era) RBAC | New `eck-operator-podmonitor-rbac.yaml` template | None (RBAC for `PodMonitor`) | None — rendered when `kisselastic.enabled` + `kisselastic.eck-operator.podMonitor.enabled` |
| Legacy Bitnami Keycloak chart | `keycloak.enabled` now explicitly `false` | None | None — already inactive on operator-based environments |

## Notes

- **redis-operator v0.24.0 label bug**: after a rolling restart the Redis pods
  lose their `redis-role=master/slave` labels, leaving `redis-ha-master`
  without endpoints (Celery workers crash). The chart ships a
  `redis-ha-label-master` CronJob (every 2 min) as the workaround — details in
  [`docs/apps/redis/redis-ha.md`](../apps/redis/redis-ha.md).
- The `RedisReplication` CRDs arrive with the ot-helm subchart on the first
  `helm upgrade`; no manual CRD apply is needed on this hop.

Full values blocks and the migration sequence: see the
[upgrade guide](4.5.16-to-4.6.4-upgrade.md).
