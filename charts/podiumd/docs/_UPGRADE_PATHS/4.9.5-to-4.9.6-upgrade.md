# Upgrade guide: PodiumD 4.9.5 → 4.9.6

> See the Confluence Releases page for the agreed application
> targets: <https://dimpact.atlassian.net/wiki/spaces/PCP/pages/7602191/Releases+PodiumD>.

For environments already on **4.9.5**. PodiumD 4.9.6 is a security patch:
new images for Open Forms and Open Inwoner, no database migrations, no
values changes. The guide has three parts:

1. **The runbook** (sections A to F): what to run, in which order, and what
   to check. Written for the deploy pipeline.
2. **Component versions and changes**: the record of what moved in the chart.
3. **Reference**: the detail per topic, for when a step fails or a choice has
   to be made.

After 4.9.6, upgrade to **4.10.1** or later, never to 4.10.0: see
[Next upgrade](#next-upgrade).

Companion documents:

- [`4.9.5-to-4.9.6-values-deltas.md`](4.9.5-to-4.9.6-values-deltas.md):
  no values changes for this hop.
- [`4.9.5-to-4.9.6-gemeente-specific.md`](4.9.5-to-4.9.6-gemeente-specific.md):
  findings per environment.

## Checklist

C, D and E per environment.

- [ ] **A. Once per cluster**: nothing for this hop.
- [ ] **B. Once per values repository**: nothing for this hop.
- [ ] **[C. Per environment, before the deploy day](#c-per-environment-before-the-deploy-day)**:
      mirror the two images.
- [ ] **[D. The deploy run](#d-the-deploy-run)**: delete the Open Inwoner
      ClamAV Job where it exists, `helm upgrade`.
- [ ] **[E. After the deploy](#e-after-the-deploy)**: check the images and
      the two applications.
- [ ] **[F. Rollback](#f-rollback)**: only when needed.

## C. Per environment, before the deploy day

### C1. Mirror the images

The registry the environment pulls from must hold both images in
[`images-4.9.6.yaml`](../images/images-4.9.6.yaml), by digest:

- `openformulieren/open-forms` 3.5.14;
- `maykinmedia/open-inwoner` 2.4.9.

### C2. Plan the window

The Open Forms and Open Inwoner pods roll to the new images. No database
migrations run, and no other component changes.

## D. The deploy run

Set the context and namespace once:

```bash
CTX=<kube context>
NS=<namespace>
```

### D1. Remove the Open Inwoner ClamAV Job

Only where `openinwoner.clamavConfigJob.enabled` is `true`. Run it directly
before `helm upgrade`; it can run twice. If it fails, nothing has changed.
It needs the right to delete Jobs in the namespace.

```bash
kubectl --context "$CTX" -n "$NS" delete job openinwoner-configure-clamav --ignore-not-found
```

Expected: `job.batch "openinwoner-configure-clamav" deleted`, or no output
when the Job does not exist. Why: see
[the Open Inwoner ClamAV Job](#reference-the-open-inwoner-clamav-job).

### D2. `helm upgrade`

Run the deploy as usual. When `clamavConfigJob` is enabled, the
`openinwoner-configure-clamav` Job runs again and configures ClamAV in Open
Inwoner.

### If the run fails

| Symptom | Cause and fix |
| --- | --- |
| `cannot patch "openinwoner-configure-clamav" with kind Job: Job.batch "openinwoner-configure-clamav" is invalid: spec.template: Invalid value: ... field is immutable` | D1 was skipped. Run D1, then the deploy again. |
| a pod cannot pull `open-forms:3.5.14` or `open-inwoner:2.4.9` | the registry lacks the image by digest: C1. |

## E. After the deploy

### E1. Check the images

```bash
kubectl --context "$CTX" -n "$NS" get pods -o jsonpath='{range .items[*]}{.spec.containers[*].image}{"\n"}{end}' | grep -E 'open-forms|open-inwoner' | sort -u
```

Expected: only `3.5.14@sha256:0320f7ba…` and `2.4.9@sha256:ae873faf…`.

### E2. Smoke tests

- Open Forms: open a form and submit it.
- Open Inwoner: the home page, a DigiD or eHerkenning login, and a page with
  the "Product Location" map plugin.

## F. Rollback

`helm rollback podiumd <last 4.9.5 revision>`. Neither release has database
migrations, so no database restore is needed. Where `clamavConfigJob` is
enabled, run D1 first: the rollback changes the Job's pod template too.

## Changes that need no action

- **Open Forms 3.5.10 → 3.5.14**: hotfixes and security updates; no
  migrations, no new settings.
- **Open Inwoner 2.4.7 → 2.4.9**: hotfixes, security updates and XSS
  hardening of the "Product Location" map plugin; no migrations, no new

## Changes

### openformulieren 3.5.10 → 3.5.14 (chart 1.12.0, unchanged)

PodiumD 4.9.6 upgrades **openformulieren** from app version 3.5.10
to 3.5.14.

- Image tag pin `openformulieren.image.tag` `3.5.10` → `3.5.14` in
  `charts/podiumd/values.yaml`.

- Image / digest: see [`images-4.9.6.yaml`](../images/images-4.9.6.yaml).

All four releases are hotfixes
([changelog](https://github.com/open-formulieren/open-forms/blob/stable/3.5.x/CHANGELOG.rst)):

- 3.5.11: updated `certifi` trust store (emSign certificate compromise); fixed
  a UI crash when configuring service fetch before a target variable is
  selected.
- 3.5.12: a service's server certificate bundle is now used for verification
  when extra root certificates are added to the instance trust store; Pillow
  security update.
- 3.5.13: the 4.0.4 certificate patch also applies to SOAP and StUF services.
- 3.5.14: security updates of `brotli`, `certifi` and `djangorestframework`.

No migrations and no new settings.

### openinwoner 2.4.7 → 2.4.9 (chart 2.4.0, unchanged)

PodiumD 4.9.6 upgrades **openinwoner** from app version 2.4.7
to 2.4.9.

- Image tag pin `openinwoner.image.tag` `2.4.7` → `2.4.9` in
  `charts/podiumd/values.yaml`.

- Image / digest: see [`images-4.9.6.yaml`](../images/images-4.9.6.yaml).

Both releases are hotfixes
([v2.4.7...v2.4.9](https://github.com/maykinmedia/open-inwoner/compare/v2.4.7...v2.4.9),
[changelog](https://github.com/maykinmedia/open-inwoner/blob/v2.4.9/CHANGELOG.rst)):

- 2.4.8: dependency updates only: `certifi` 2026.10.19, `brotli` 1.2.1,
  Pillow 13.0.0, `djangorestframework` 3.18.3 and Django 5.2.18.
- 2.4.9: location pop-ups of the "Product Location" CMS plugin are built from
  DOM elements instead of HTML text (XSS hardening); the PDF exports of the
  jaaropgave and maandspecificatie have their layout back; display fixes in
  the "Mijn afspraken" plugin and page; `PyJWT` 2.15.1, `urllib3` 2.8.0 and
  `geopy` 2.5.0.

No migrations and no new settings.

## Next upgrade

From 4.9.6, the next upgrade is **4.10.1** or later, with the 4.9.6 → 4.10.1
guide (`4.9.6-to-4.10.1-upgrade.md`) that comes with 4.10.1. Stay on 4.9.6
until 4.10.1 is released. Do not upgrade 4.9.6 to 4.10.0: 4.10.0 was released
before these patches and ships Open Inwoner 2.4.7, so it would undo the 2.4.9
fixes. 4.10.1 carries the same fixes as 4.9.6. Environments on 4.9.5 can still
upgrade to 4.10.0.

## Reference: the Open Inwoner ClamAV Job

In 4.9.x `openinwoner-configure-clamav` has a fixed name and, by default, no
`ttlSecondsAfterFinished`, so the Job stays after it finishes. Kubernetes
does not allow a Job's pod template to change, and the new Open Inwoner image
changes it: without D1, `helm upgrade` fails. From 4.10.0 the Job's name
carries a hash of its pod template, so a new image creates a new Job and the
step is not needed there.
