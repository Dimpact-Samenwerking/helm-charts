# Upgrade guide: PodiumD 4.8.5 → 4.9.0

> See the Confluence Releases page for the agreed application
> targets: <https://dimpact.atlassian.net/wiki/spaces/PCP/pages/7602191/Releases+PodiumD>.

This is the upgrade guide for environments already on **4.8.5**, as shipped on
the Info branch (`feature/info-podiumd-4.9-next`). Two components move, and
both move their Helm chart as well as their image. There are no gemeente
`podiumd.yml` changes.

> **Which 4.9.0 is this?** The Info branch pins a different ZAC and ZGW Office
> Add-in set than the 4.9.0 integration branch does. The integration branch
> holds ZAC at `5.1.0` (chart `1.0.297`, unchanged) and the Add-in at
> `v0.9.352` (chart `0.0.89`, unchanged); those are the versions described by
> [`images-4.9.0.yaml`](../images/images-4.9.0.yaml). This branch is ahead on
> both. Mirror from [`images-info.yaml`](../images/images-info.yaml) for this
> branch — see the ACR step below.

## Component versions (4.9.0 vs 4.8.5)

| Component | App version | Helm chart | Notes |
| --- | --- | --- | --- |
| ZAC (Zaakafhandelcomponent) | 5.0.2 → 5.6.0 | 1.0.297 → 1.0.301 | five minor versions — see below |
| ZGW Office Add-in (frontend + backend) | v0.9.313 → 0.11.0 | 0.0.89 → 0.0.91 | version scheme drops the `v` prefix |

## Changes

### ZAC 5.0.2 → 5.6.0 (Helm chart 1.0.297 → 1.0.301)

PodiumD 4.9.0 on this branch advances **ZAC (Zaakafhandelcomponent)** by five
minor versions, from 5.0.2 to 5.6.0, and moves the chart line from `1.0.297`
to `1.0.301`. This is a larger application jump than the chart-version delta
suggests: `1.0.297` was already tested upstream against app 5.5.0 with the
image deliberately held back (see the
[4.8.4 → 4.8.5 guide](4.8.4-to-4.8.5-upgrade.md#zac-501--502-helm-chart-10251--10297)
for why the chart and image versions were decoupled), so most of the
application change here arrives inside a chart line that had already caught up.

- Image tag pin `zac.image.tag` `5.0.2` → `5.6.0` in
  `charts/podiumd/values.yaml`, plus the `Chart.yaml` dependency bump.
- Image / digest: see [`images-info.yaml`](../images/images-info.yaml).

**No `podiumd.yml` action required.** The chart-level changes are the ZAC image
tag and the dependency version; every environment inherits both from the chart
defaults (gemeente `podiumd.yml` files override `registry`/`repository` for
their own ACR mirror but never `tag`). The ZAC sidecar images
(nginx-unprivileged, curl, busybox, gotenberg, opa) are unchanged from 4.8.5.

> Because this crosses five minor versions rather than one, read the ZAC
> release notes for 5.1 through 5.6 before upgrading a gemeente that
> configures ZAC beyond the defaults — BRP protocollering and PABC
> integration are the usual candidates. `zac.brpApi.protocollering.verwerking
> .extendWithZaaktype` (introduced in the 4.8.5 hop) still exists and needs
> nothing redone here.

> The 4.8.4 → 4.8.5 guide told environments **not** to enable
> `zac.auth.enablePkce`, because the 5.0.2 image had no PKCE support. That
> constraint was written against 5.0.2 and has not been re-validated against
> 5.6.0 — treat PKCE as unverified on this branch rather than as either
> supported or blocked.

### ZGW Office Add-in v0.9.313 → 0.11.0 (Helm chart 0.0.89 → 0.0.91)

PodiumD 4.9.0 on this branch upgrades the **ZGW Office Add-in** frontend and
backend from `v0.9.313` to `0.11.0`, and the chart from `0.0.89` to `0.0.91`.
Note the version scheme changed: the new tags carry no `v` prefix. This image
was not touched by the 4.8.4 or 4.8.5 hops, so the delta is the same whether an
environment is coming from 4.8.2 or 4.8.5.

- Image tag pins `zgw-office-addin.frontend.image.tag` and
  `zgw-office-addin.backend.image.tag` updated in
  `charts/podiumd/values.yaml`, plus the `Chart.yaml` dependency bump.
- Image / digests: see [`images-info.yaml`](../images/images-info.yaml).

**No `podiumd.yml` action required.** As with ZAC, the tags come from the chart
defaults; environments only override `registry`/`repository`. The repository
names (`zgw-office-addin-{frontend,backend}`, hyphen already dropped) are
unchanged from 4.8.5.

## Per-environment checklist

Read the whole guide once first. Then, for **every environment** you upgrade,
work through this list top to bottom. There are no gemeente-values edits this
hop — see [`4.8.5-to-4.9.0-values-deltas.md`](4.8.5-to-4.9.0-values-deltas.md).

### A. Prepare

- [ ] **ACR mirror**: mirror the image set under the strip-registry names from
      [`images-info.yaml`](../images/images-info.yaml) — `infonl/zaakafhandelcomponent`
      `5.6.0`, and `infonl/zgw-office-addin-frontend` / `-backend` `0.11.0`.
      Do **not** mirror from `images-4.9.0.yaml` on this branch: it lists ZAC
      `5.1.0`, which the chart does not request, so the pull would fail on a
      registry that only carries what was mirrored.
- [ ] If this environment configures ZAC beyond the chart defaults (BRP
      protocollering, PABC), review the ZAC 5.1 → 5.6 release notes for
      behaviour changes before upgrading.

### B. Deploy

- [ ] Run the deploy pipeline / `helm upgrade`.

### C. Verify

- [ ] ZAC pod reaches ready and its `/health/ready` endpoint reports
      `overall: UP` — in particular `OpenZaakReadinessHealthCheck`,
      `SolrReadinessHealthCheck` and `PabcReadinessHealthCheck`, which gate
      readiness and will hold the deployment at `0/1` if any of them is DOWN.
- [ ] ZAC OPA and Gotenberg sidecars and the `signaleren` CronJob start
      cleanly (watch for read-only-filesystem write failures in pod
      logs/events, unchanged from the 4.8.5 hardening).
- [ ] Office Add-in frontend and backend pods pull and start on the new
      `0.11.0` tags — a stale ACR mirror shows here first as `ImagePullBackOff`.
- [ ] If BRP protocollering is enabled: confirm
      `BRP_VERWERKINGSREGISTER_EXT_WITH_ZAAKTYPE` is still set as expected in
      the ZAC ConfigMap after the five-version jump.
