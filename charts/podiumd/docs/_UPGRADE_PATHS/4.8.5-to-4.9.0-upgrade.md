# Upgrade guide: PodiumD 4.8.5 → 4.9.0

> See the Confluence Releases page for the agreed application
> targets: <https://dimpact.atlassian.net/wiki/spaces/PCP/pages/7602191/Releases+PodiumD>.

This is the upgrade guide for environments already on **4.8.5** (the current
stable baseline). No `podiumd.yml` changes are required for this hop — every
change below ships in the chart's own defaults.

## Changes

### ZAC 5.0.2 → 5.1.0 (chart 1.0.297, unchanged)

PodiumD 4.9.0 upgrades **ZAC (Zaakafhandelcomponent)** from app version 5.0.2
to 5.1.0. The Helm chart stays on `1.0.297` — that chart line was already
bumped ahead of the image in the 4.8.5 hop (tested upstream against app
5.5.0, image deliberately held back); 4.9.0 simply advances the image within
that same chart line instead of bumping the chart again. See the
[4.8.4 → 4.8.5 guide](4.8.4-to-4.8.5-upgrade.md#zac-501--502-helm-chart-10251--10297)
for why the chart and image versions were decoupled in the first place.

- Image tag pin `zac.image.tag` `5.0.2` → `5.1.0` in
  `charts/podiumd/values.yaml`. No `Chart.yaml` change.
- Image / digest: see [`images-4.9.0.yaml`](../images/images-4.9.0.yaml).

**No `podiumd.yml` action required.** The only chart-level change is the ZAC
image tag, which every environment inherits from the chart default (gemeente
`podiumd.yml` files override `registry`/`repository` for their own ACR mirror
but never `tag`). The ZAC sidecar images (nginx-unprivileged, curl, busybox,
gotenberg, opa) are unchanged from 4.8.5.

> `zac.brpApi.protocollering.verwerking.extendWithZaaktype` (introduced in the
> 4.8.5 hop) is unchanged in 5.1.0; nothing to redo here. For application-level
> behaviour changes between ZAC 5.0.2 and 5.1.0, see the ZAC release notes.

### ZGW Office Add-in v0.9.313 → v0.9.352 (chart 0.0.89, unchanged)

PodiumD 4.9.0 upgrades the **ZGW Office Add-in** frontend and backend from
`v0.9.313` to `v0.9.352`. The Helm chart version remains `0.0.89`. This
image was not touched by the 4.8.4 or 4.8.5 hops, so the delta is the same
whether an environment is coming from 4.8.2 or 4.8.5.

- Image tag pins `zgw-office-addin.frontend.image.tag` and
  `zgw-office-addin.backend.image.tag` updated in
  `charts/podiumd/values.yaml`.
- Image / digests: see [`images-4.9.0.yaml`](../images/images-4.9.0.yaml).

**No `podiumd.yml` action required.** As with ZAC, the tags come from the chart
defaults; environments only override `registry`/`repository`. The repository
names (`zgw-office-addin-{frontend,backend}`, hyphen already dropped) are
unchanged from 4.8.5.

### ClamAV 1.5.2 → 1.5.4 (chart 3.7.1 → 3.7.2)

Image tag pin `clamav.image.tag` in `charts/podiumd/values.yaml`, plus the
`clamav` Helm chart dependency version. No config or schema changes.

- Image / digest: see [`images-4.9.0.yaml`](../images/images-4.9.0.yaml).

**No `podiumd.yml` action required.**

### Kiss's ECK-managed Elasticsearch/Kibana/Enterprise Search 8.19.3 → 8.19.19

16 patches on the same 8.19.x branch, applied to all three
`kiss-eck.eck-elasticsearch` / `eck-kibana` / `eck-enterprise-search`
`version:` fields in lockstep. Elastic 8.x end-of-maintenance is
2027-01-15, end-of-support 2027-07-15.

- Image / digests: see [`images-4.9.0.yaml`](../images/images-4.9.0.yaml).

**No `podiumd.yml` action required.**

### ECK Operator 3.4.0 → 3.5.0 + ECK Stack (kiss-eck) 0.19.0 → 0.20.0

The `eck-operator` chart bump also moves its bundled operator image from
`3.4.0` to `3.5.0` (the chart's `image.tag` floats on `appVersion`, and
podiumd doesn't override it). The CRD schema change was verified
additive-only — see [operators & CRDs](4.8.5-to-4.9.0-operators-crds.md) for
the full diff method and results. The `eck-stack` (alias `kiss-eck`) chart
bump to `0.20.0` ships no image of its own.

- Image / digest: see [`images-4.9.0.yaml`](../images/images-4.9.0.yaml).

**No `podiumd.yml` action required.**

### Keycloak app image 26.6.4 → 26.7.2

App image only — `keycloak.image.tag` in `charts/podiumd/values.yaml`. The
`keycloak-operator` chart stays on `1.12.1`: no operator release yet supports
Keycloak 26.7.x. The operator's own `RELATED_IMAGE_KEYCLOAK` reference
(`keycloak-operator.config.keycloakImage`) is kept in sync with the app image
per the requirement documented in that block's `values.yaml` comment.

- Image / digest: see [`images-4.9.0.yaml`](../images/images-4.9.0.yaml).

**No `podiumd.yml` action required.**

### Python (ensurePodiumdAdminUser init image) 3.14-slim → 3.14.7-slim

The PBKDF2-hash init container for the `ensurePodiumdAdminUser` job now pins
a specific patch (`3.14.7-slim`) instead of the floating `3.14-slim` minor
tag. No behavior change expected — same Python minor line.

- Image / digest: see [`images-4.9.0.yaml`](../images/images-4.9.0.yaml).

**No `podiumd.yml` action required.**

## Per-environment checklist

Read the whole guide once first. Then, for **every environment** you upgrade,
work through this list top to bottom. There are no gemeente-values edits this
hop — see [`4.8.5-to-4.9.0-values-deltas.md`](4.8.5-to-4.9.0-values-deltas.md).

### A. Prepare

- [ ] **ACR mirror**: mirror the full 4.9.0 image set under the strip-registry
      names ([`images-4.9.0.yaml`](../images/images-4.9.0.yaml)) — ZAC `5.1.0`,
      ZGW Office Add-in `v0.9.352` frontend/backend, ClamAV `1.5.4`, Keycloak
      `26.7.2`, ECK Operator `3.5.0`, Kiss's Elasticsearch/Kibana/Enterprise
      Search `8.19.19`, and Python `3.14.7-slim`.
- [ ] Read [operators & CRDs](4.8.5-to-4.9.0-operators-crds.md) — the ECK
      Operator bump carries a CRD schema change (additive-only, no adoption
      step needed, but read it before the deploy).

### B. Deploy

- [ ] Run the deploy pipeline / `helm upgrade`.
