# Upgrade guide: PodiumD 4.9.4 → 4.9.5

> See the Confluence Releases page for the agreed application
> targets: <https://dimpact.atlassian.net/wiki/spaces/PCP/pages/7602191/Releases+PodiumD>.

This is the upgrade guide for environments already on **4.9.4**.

PodiumD 4.9.5 brings Open Forms 3.5.10, which fixes the tool that converts
forms to the new logic evaluation. Every environment must do that conversion
before PodiumD 4.10.0 (Open Forms 4.0), so 4.9.5 is the release to do it on.

## After you deploy (every environment)

- **Save the forms converted earlier.** Open Forms 3.5.2 to 3.5.9 (PodiumD
  4.9.0 to 4.9.4) can give logic rules the wrong order when forms are
  converted with `enable_new_logic_evaluation_for_all_forms`. Rules then run
  in the wrong order: wrong fields are shown or hidden, wrong values computed.
  If the environment used that command, open each converted form in the
  admin and save it once; that sets the correct order again. Forms saved
  after the conversion are fine. The dry run below cannot list them: it only
  looks at forms that are not converted yet. List the converted forms with:

  ```bash
  kubectl exec -n <ns> <openformulieren-pod> -- \
    python /app/src/manage.py shell -c "from openforms.forms.models import Form; [print(f.pk, f.admin_name) for f in Form.objects.filter(_is_deleted=False, new_logic_evaluation_enabled=True)]"
  ```

  This also lists forms that were switched to the new logic evaluation one
  by one in the admin; saving those again does no harm.
- **Convert the remaining forms**, now that the command is fixed:

  ```bash
  # Dry run: lists converted forms and forms with problems, changes nothing
  kubectl exec -n <ns> <openformulieren-pod> -- \
    python /app/src/manage.py enable_new_logic_evaluation_for_all_forms
  # Apply
  kubectl exec -n <ns> <openformulieren-pod> -- \
    python /app/src/manage.py enable_new_logic_evaluation_for_all_forms --no-dry-run
  ```

  Forms with cyclic logic rules are listed and must be fixed by hand. Open
  Forms 4.0 refuses to upgrade while a form still uses the old logic
  evaluation; see
  [`openforms-migration-preparation.md`](../apps/openforms/openforms-migration-preparation.md).
- **Test forms with the `customerProfile` component.** Open Forms backported
  email verification into it in 3.5.10 and recommends testing those forms
  extensively before production.

## Changes

### openformulieren 3.5.8 → 3.5.10 (chart 1.12.0, unchanged)

PodiumD 4.9.5 upgrades **openformulieren** from app version 3.5.8
to 3.5.10.

- Image tag pin `openformulieren.image.tag` `3.5.8` → `3.5.10` in
  `charts/podiumd/values.yaml`.

- Image / digest: see [`images-4.9.5.yaml`](../images/images-4.9.5.yaml).

Release notes:
[3.5.9](https://github.com/open-formulieren/open-forms/blob/master/CHANGELOG.rst#359-2026-09-18)
and
[3.5.10](https://github.com/open-formulieren/open-forms/blob/master/CHANGELOG.rst#3510-2026-10-08).

- **4.0 migration tooling:** fixed the logic analysis assigning the wrong
  rule order (#6275), improved the bulk logic conversion command (#6710) and
  the `clearOnHide` check script (#6668).
- **Backported feature:** email verification in the `customerProfile`
  component (#6426).
- **Opt-in:** `CUSTOMER_INTERACTIONS_USE_REFERENCE_FOR_STANDARD_ADDRESS=True`
  makes the legacy Open Klant mechanism send the `referentie` when updating
  customer profile preferences (#6418). PodiumD does not set it.
- **Bug fixes:** textarea newlines in the confirmation PDF, the JSON editor
  component, prefill logging, the form theme on resume pages and
  confirmation emails, file upload components from old form versions, a
  logic crash on incomplete `date`/`datetime` input, phone number
  validation, and customer profile address validation.
- **Security:** Django and soupsieve updates.

### openinwoner 2.4.6 → 2.4.7 (chart 2.4.0, unchanged)

PodiumD 4.9.5 upgrades **openinwoner** from app version 2.4.6
to 2.4.7.

Image bump only; no chart, values or database changes. Release notes:
[2.4.7](https://github.com/maykinmedia/open-inwoner/blob/v2.4.7/CHANGELOG.rst#247-2026-10-14).

- **Security:** `maykin-django-prosemirror` 0.12.0 fixes GHSA-c8x8-7fp4-3x9w:
  pasting malicious HTML into the CMS editor could run JavaScript in the
  browser. Only administrators and editors are at risk.
- **Bug fixes:** CMS apphook pages ("Samenwerken", "Mijn profiel") can be
  switched to structure mode and published again (#3075); the CMS structure
  view offers every plugin a placeholder allows again, not only the text
  plugin (#3059); creating a page with the CMS wizard no longer fails with a
  `TypeError` (#3088, `django-formtools` 2.3 → 2.7).

- Image tag pin `openinwoner.image.tag` `2.4.6` → `2.4.7` in
  `charts/podiumd/values.yaml`.

- Image / digest: see [`images-4.9.5.yaml`](../images/images-4.9.5.yaml).
