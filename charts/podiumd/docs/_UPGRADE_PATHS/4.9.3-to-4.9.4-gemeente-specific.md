# Gemeente-specific notes — PodiumD 4.9.3 → 4.9.4

Findings for this hop that apply to a **specific gemeente or environment** —
not to the release in general — are collected here: data quirks, local
overrides, hosting particulars, incident follow-ups.

## dim1 (accp), gene (accp) — SSCHostingSync; dim2 (ontw), dim3 (ontw) — ExternalsPodiumD

- `openinwoner.image.repository` is `acrprodmgmt.azurecr.io/openinwoner`, a
  mirror under the old component-named scheme. All other environments pull from
  `<acr>/maykinmedia/open-inwoner`. A mirror run from
  [`images-4.9.4.yaml`](../images/images-4.9.4.yaml) puts 2.4.5 only under
  `maykinmedia/open-inwoner`, so these four would fail to pull 2.4.5.
- **Before deploying 4.9.4,** either push 2.4.5 (digest
  `sha256:8267c7d49934c142f54a4ef8934425808ecfb1998a34f88f0e4a1d6ea2f577e6`) to
  `acrprodmgmt.azurecr.io/openinwoner`, or set the repository to
  `acrprodmgmt.azurecr.io/maykinmedia/open-inwoner`, like the other
  environments. The second option is preferred: it ends the old naming.
- Checked: SSCHostingSync `main` and ExternalsPodiumD `release/podiumd-4.9.x`
  (2026-10-07).
