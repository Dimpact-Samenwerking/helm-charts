## ECK CRD adoption — once per cluster, before the first 4.8.0 deploy

On clusters where the ECK CRDs already exist without `podiumd` release
ownership (kisselastic era), Helm refuses to upgrade them
(`invalid ownership metadata`). Deploying with **stale** CRDs crashloops the
operator. The helper script adopts the CRDs, checks the RabbitMQ drain and
records the Elasticsearch baseline in one go:

```bash
charts/podiumd/scripts/pre-upgrade-prep-4.8.0.sh --context <kubectl-context>
```

After adoption the chart keeps the CRDs in lock-step with the operator on
every upgrade — the deploy pipeline needs no changes.

- ACR mirror: `elastic/eck-operator:3.4.0`
  ([`images-baseline.yaml`](../images/images-baseline.yaml)).
- Full runbook, incl. the `--take-ownership` alternative:
  [`migrating-to-eck-stack.md`](../apps/elastic/migrating-to-eck-stack.md)
  (section 4b).
