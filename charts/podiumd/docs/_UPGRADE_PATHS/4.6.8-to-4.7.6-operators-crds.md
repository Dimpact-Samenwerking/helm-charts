# Operators & CRDs — PodiumD 4.6.8 → 4.7.6

Companion to [`4.6.8-to-4.7.6-upgrade.md`](4.6.8-to-4.7.6-upgrade.md)
(consolidated guide).

| Component | Change | CRD impact | Action |
|---|---|---|---|
| keycloak-operator (at 4.7.3) | Operator image → `26.6.x` while the adfinis subchart stays `1.11.4` | **`k8s.keycloak.org` CRDs must move `v2alpha1` → `v2beta1`** — the operator `CrashLoopBackOff`s without it | Run `install-keycloak-operator-crds.sh` before the deploy, then restart the operator |
| keycloak-operator (at 4.7.4) | Operator + server `26.6.2` → `26.6.3`; adfinis chart `1.11.4` → `1.12.0` | **None** — the 26.6.3 CRDs are byte-identical to 26.6.2 and adfinis 1.12.0 bundles the matching set | Mind the `operator.image.sha` digest-pin caveat ([4.7.3-to-4.7.4 notes](4.7.3-to-4.7.4-operators-crds.md)) |

## Keycloak CRD upgrade (`v2alpha1` → `v2beta1`) — once, at the 4.7.3 step

```bash
# 1. Inspect what would be applied
charts/podiumd/scripts/install-keycloak-operator-crds.sh --dry-run

# 2. Install upstream CRDs (adds v2beta1, keeps v2alpha1 deprecated/served)
charts/podiumd/scripts/install-keycloak-operator-crds.sh \
  --context "$CTX"

# 3. Restart the operator so it re-establishes informers
kubectl --context "$CTX" -n "$NS" rollout restart deploy keycloak-operator
```

No further CRD action for the rest of the 4.7.x line. Background and
verification:
[upgrade guide § Keycloak CRD upgrade](4.6.8-to-4.7.6-upgrade.md#keycloak-crd-upgrade-v2alpha1--v2beta1).
