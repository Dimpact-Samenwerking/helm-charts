## C. Per environment, before the deploy day

### C1. Mirror the images

The registry the environment pulls from must hold everything in
[`images-4.10.2.yaml`](../images/images-4.10.2.yaml), by digest. Renamed
this release, so a mirror run by the old name misses it:

- `nginx/nginx-unprivileged` 1.31.9 (replaces the archived
  `nginxinc/nginx-unprivileged`).

A mirror kept under another path is fine, as long as it holds the 1.31.9
digest pulled from `docker.io/nginx/nginx-unprivileged`. That covers a
`repository:` override such as `<acr>/nginx-unprivileged` or
`<acr>/nginxinc/nginx-unprivileged` on any of the paths listed in
[nginx-unprivileged](#nginx-unprivileged-1317--1319). The old repository
never published 1.31.9, so a mirror that still syncs from
`docker.io/nginxinc/nginx-unprivileged` fails to pull on every nginx
sidecar, the API proxy and the Frank!Gateway dashboard shim.

Re-published under the same tag (the manifest marks it "digest changed"):

- `alpine/k8s` 1.37.2, now `sha256:7a82aeef…`. It runs the zookeeper-operator
  hooks, the redis-ha Jobs and CronJob, the ZAC restart Job and the Maykin
  configuration wait hook.

A mirror that skips a name and tag it already has keeps the old digest, and
the pull fails. Copy with `skopeo copy --all --preserve-digests`: without
`--preserve-digests` a copy can store the manifest under another digest.

### If the run fails

| Symptom | Fix |
| --- | --- |
| `ensure-keycloak-operator-sa` fails with `FATAL: podiumd-admin cannot log in to the master realm with a password`: client `keycloak-operator` exists in the master realm with another secret, and master's login flow refuses a password-only login (for example because it requires OTP) | set `keycloak-operator.jobs.ensureOperatorSa.clientSecret` to that client's secret, or enter the value of `keycloak-operator.jobs.ensureOperatorSa.clientSecret` as the client's secret in the admin console (Clients → keycloak-operator → Credentials), or delete the client so the next deploy creates it; then deploy again |
| a pod cannot pull `alpine/k8s:1.37.2` (the zookeeper-operator hook fails `helm upgrade`; the redis-ha label-master CronJob, the ZAC restart Job or a Maykin configuration wait hook stay in `ImagePullBackOff`) | the registry lacks the new digest: C1. |

## Changes that need no action

- **The `keycloak-operator` client no longer depends on master's login
  flows** (podiumd-chart-55): `ensure-keycloak-operator-sa` creates a missing
  client with Keycloak's `kc.sh bootstrap-admin service`, straight against the
  Keycloak database, instead of logging in as `podiumd-admin` with a password.
  An environment whose master realm requires OTP in the direct grant flow then
  no longer hangs the realm imports. The Job has two init containers with the
  Keycloak image (`keycloak-operator.jobs.ensureOperatorSa.resources`). The
  client it creates is marked as a temporary admin in the admin console. A
  client that exists with another secret still needs a password login as
  `podiumd-admin`; when master refuses that, the Job fails at once (see
  [If the run fails](#if-the-run-fails)) instead of retrying for over an hour.

## Changes

### nginx-unprivileged 1.31.7 → 1.31.9

PodiumD 4.10.2 upgrades the shared **nginx-unprivileged** image to 1.31.9,
pinned at:

- `global.images.nginx.tag` `1.31.7` → `1.31.9`
- `openzaak.nginx.image.tag` `1.31.7` → `1.31.9` (shares a YAML anchor with `global.images.nginx.tag`)
- `openarchiefbeheer.nginx.image.tag` `1.31.7` → `1.31.9` (shares a YAML anchor with `global.images.nginx.tag`)
- `openklant.nginx.image.tag` `1.31.7` → `1.31.9` (shares a YAML anchor with `global.images.nginx.tag`)
- `openformulieren.nginx.image.tag` `1.31.7` → `1.31.9` (shares a YAML anchor with `global.images.nginx.tag`)
- `openinwoner.nginx.image.tag` `1.31.7` → `1.31.9` (shares a YAML anchor with `global.images.nginx.tag`)
- `openbeheer.nginx.image.tag` `1.31.7` → `1.31.9` (shares a YAML anchor with `global.images.nginx.tag`)
- `zac.nginx.image.tag` `1.31.7` → `1.31.9` (shares a YAML anchor with `global.images.nginx.tag`)
- `apiproxy.image.tag` `1.31.7` → `1.31.9` (shares a YAML anchor with `global.images.nginx.tag`)
- `frankgateway.dashboard.auth.shim.image.tag` `1.31.7` → `1.31.9` (shares a YAML anchor with `global.images.nginx.tag`)

- Image / digest: see [`images-4.10.2.yaml`](../images/images-4.10.2.yaml).

The repository moves from `nginxinc/nginx-unprivileged` to
`nginx/nginx-unprivileged` (`global.images.nginx.repository`, shared by all
the paths above). Docker Hub archived the `nginxinc` repository; its last
release is 1.31.7. The new repository builds the same image (port 8080, PID
file in `/tmp`, uid 101), but with its own digests. Mirror it first:
[C1](#c1-mirror-the-images).
