## Changes

### Namespace portability (Redis, allowedHosts, ClamAV, Kibana)

Cluster-internal references that previously hard-coded the `podiumd` namespace are now
namespace-relative, so the chart can be deployed into any namespace:

- Redis connection strings use the bare service name `redis-ha-master` (was
  `redis-ha-master.podiumd.svc.cluster.local`).
- Django `allowedHosts` use the wildcard `.svc.cluster.local` (was `<svc>.podiumd.svc.cluster.local`).
- `clamavHost` uses the bare `clamav`; KISS Kibana uses the bare `kiss-kb-http:5601`.

**No action required for deployments in the `podiumd` namespace** — the bare names and wildcard
resolve identically there.

**Deploying to a different namespace:** three operator watch-scopes cannot be templated in
`values.yaml` and must be set to your namespace:
`eck-operator.managedNamespaces`, `zac.solr-operator.watchNamespaces`,
`zac.solr-operator.zookeeper-operator.watchNamespace`. Use
`charts/podiumd/ci/values-namespace-scope.example.yaml` (copy + replace `<namespace>`) or the
`--set` snippet in
[docs/misc/deploying-to-a-custom-namespace.md](../misc/deploying-to-a-custom-namespace.md).
