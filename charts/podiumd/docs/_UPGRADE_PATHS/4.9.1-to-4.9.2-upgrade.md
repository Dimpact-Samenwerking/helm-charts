## Changes

### postgres 16-alpine → 16.15-alpine

PodiumD 4.9.2 moves both postgres client jobs onto one new shared image,
`global.images.postgres` (`library/postgres:16.15-alpine`), which
`openbao.database.schemaJob.image` and
`keycloak-operator.jobs.ensurePodiumdAdminUser.image` now reference:

- `openbao.database.schemaJob.image.tag` `16-alpine` → `16.15-alpine` — the
  same digest, so the image itself does not change.
- `keycloak-operator.jobs.ensurePodiumdAdminUser.image` `postgres:16.15`
  (Debian) → `library/postgres:16.15-alpine`. Both jobs only run `psql` and
  `pg_isready`.

- Image / digest: see [`images-4.9.2.yaml`](../images/images-4.9.2.yaml).

### Open Formulieren 3.5.6 → 3.5.8

PodiumD 4.9.2 upgrades **Open Formulieren** from app version 3.5.6 to 3.5.8,
pinned at:

- `openformulieren.image.tag` `3.5.6` → `3.5.8`

Both 3.5.7 and 3.5.8 are regular bugfix releases (per upstream
[`CHANGELOG.rst`](https://github.com/open-formulieren/open-forms/blob/3.5.8/CHANGELOG.rst)) —
no breaking changes, no migration steps. Helm chart `openforms` stays at
`1.12.0` in `charts/podiumd/Chart.yaml`; only the app image tag moves.

Notable fixes: `addressNL` component incorrectly treated as required
(6581), pre-registration failures not reported in the email digest (6497),
logic evaluation giving different outcomes for admin vs non-admin users
(6468/6507), plus SDK 3.5.7/3.5.8 renderer fixes and backend dependency
security patches.

- Image / digest: see [`images-4.9.2.yaml`](../images/images-4.9.2.yaml).

#### Action required

None beyond the normal rollout — no `podiumd.yml` changes, no manual steps.

### PABC: realm roles per functional role (IN-2004)

ZAC 5.4.x sends the user's Keycloak **realm roles** (`realm_access.roles`) to
PABC as functional roles, not the group names from `group_membership`. With
only groups, PABC returns no application roles and every user sees
"u heeft geen toestemming om deze pagina te bekijken".

- With `keycloak.config.skipRoles`/`skipGroups: false` the realm import now
  creates a realm role per functional role in `files/pabc-dataset.json`
  (currently `administrators`, `behandelaars`, `beheerders`, `coordinators`,
  `raadplegers` and `recordmanagers`) and attaches each one to the group of
  the same name.
- New `pabc.seedJob.keycloak.enabled` (default `true`, but only active
  together with `pabc.seedJob.enabled`, which defaults to `false`) runs
  `pabc-keycloak-groups-job-<checksum>`. Per functional role in
  `files/pabc-dataset.json` it creates the realm role and the group if missing
  and attaches the role to the group. Additive only. Needs
  `keycloak-operator.jobs.ensureOperatorSa.clientSecret`.
- **No effect on municipalities** that keep the defaults: `pabc.seedJob.enabled:
  false` and `skipRoles`/`skipGroups: true`. They map their own realm roles
  to functional roles in the PABC UI.
- No new image: the Job reuses `keycloak.image`.
- Users still have to be put in the groups. PABC only grants rights for the
  entity types (zaaktypen) linked to a domain in PABC.
- See [enabling-pabc.md](../apps/pabc/enabling-pabc.md) and
  [pabc-iam-migration.md](../apps/pabc/pabc-iam-migration.md).

### Contact (KISS) 3.1.1 → 3.1.3

Patch release van KISS-Frontend en kiss-elastic-sync. Geen values-wijzigingen.

- `kiss.image.tag` en `kiss.settings.syncJobs.elasticSyncImage.tag` → `3.1.3`
- Images / digests: zie [`images-4.9.2.yaml`](../images/images-4.9.2.yaml).

### Interne Taak Afhandeling 3.3.0 → 3.3.2

Web en poller naar 3.3.2. De values-structuur uit 3.3.0 blijft gelijk
(`ita.poller.image` voor beide CronJobs, `ita.nieuweInternetaakNotificatie`
voor de bestaande poller).

- Nieuw in de subchart: `ita.verlopenContactverzoekHerinneringNotificatie`
  (`enabled: true`, `schedule: "0 7 * * 1-5"`) stuurt op werkdagen om 07:00 een
  herinneringsmail voor openstaande contactverzoeken, per medewerker en per
  afdeling. Zet `enabled: false` om die mail uit te zetten.
- `ita.web.image.tag` en `ita.poller.image.tag` → `3.3.2`
- Images / digests: zie [`images-4.9.2.yaml`](../images/images-4.9.2.yaml).

## Corrections to the 4.9.0 → 4.9.1 documentation

Information that was missing or wrong in the 4.9.1 release of these documents,
corrected in place with PodiumD 4.9.2:

- **mi-data Helm chart 1.0.0 → 1.1.0.** The 4.9.0 → 4.9.1
  [upgrade guide](4.9.0-to-4.9.1-upgrade.md) and
  [values deltas](4.9.0-to-4.9.1-values-deltas.md) gave the chart as

  1.1.0; nothing extra is needed for 4.9.2.
