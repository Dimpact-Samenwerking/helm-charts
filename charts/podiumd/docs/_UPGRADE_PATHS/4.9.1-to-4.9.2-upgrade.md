## PABC: realm roles per functional role (IN-2004)

ZAC 5.4.x sends the user's Keycloak **realm roles** (`realm_access.roles`) to
PABC as functional roles, not the group names from `group_membership`. With
only groups, PABC returns no application roles and every user sees
"u heeft geen toestemming om deze pagina te bekijken".

- With `keycloak.config.skipRoles`/`skipGroups: false` the realm import now
  creates a realm role per functional role in `files/pabc-dataset.json`
  (currently `administrators`, `behandelaars`, `beheerders`, `coordinators`,
  `raadplegers` and `recordmanagers`) and attaches each one to the group of
  the same name.
- New `pabc.seedJob.keycloak.enabled` (default `true`, but only active
  together with `pabc.seedJob.enabled`, which defaults to `false`) runs
  `pabc-keycloak-groups-job-<checksum>`. Per functional role in
  `files/pabc-dataset.json` it creates the realm role and the group if missing
  and attaches the role to the group. Additive only. Needs
  `keycloak-operator.jobs.ensureOperatorSa.clientSecret`.
- **No effect on municipalities** that keep the defaults: `pabc.seedJob.enabled:
  false` and `skipRoles`/`skipGroups: true`. They map their own realm roles
  to functional roles in the PABC UI.
- No new image: the Job reuses `keycloak.image`.
- Users still have to be put in the groups. PABC only grants rights for the
  entity types (zaaktypen) linked to a domain in PABC.
- See [enabling-pabc.md](../apps/pabc/enabling-pabc.md) and
  [pabc-iam-migration.md](../apps/pabc/pabc-iam-migration.md).

## Keycloak client URLs: no more `example.nl` defaults

The chart no longer ships `example.nl` placeholders for the URLs that Keycloak
client redirect URIs are built from. They now default to `""`, and the render
fails while the component or client is enabled and the value is empty or still
an `example.nl` URL. Before, a missing value rendered a valid-looking client
whose redirect URIs pointed at `example.nl`: the deploy succeeded and every
login failed with `Invalid parameter: redirect_uri`.

The check now covers every Keycloak client that has redirect URIs:

| Component / client | Value | Skipped when |
| --- | --- | --- |
| Django apps (openzaak, opennotificaties, objecten, objecttypen, openarchiefbeheer (`abc`), openklant, openformulieren, openinwoner, referentielijsten, openbeheer), openbao | `<component>.configuration.oidcUrl` | `<component>.enabled: false` |
| kiss | `kiss.configuration.oidcUrl` | `kiss.enabled: false` |
| zac | `zac.contextUrl` | `zac.enabled: false` |
| pabc | `pabc.settings.oidc.oidcUrl` | `pabc.enabled: false` |
| ita | `ita.web.oidc.frontendUrl` (was `REP_ITA_OIDC_FRONTEND_URL_REP`) | `ita.enabled: false` |
| zaakbrug | `keycloak.config.clients.zaakbrug.oidcUrl` | `zaakbrug.enabled: false` or `keycloak.config.clients.zaakbrug.enabled: false` |
| monitoring | `keycloak.config.clients.monitoring.oidcUrl` | `keycloak.config.clients.monitoring.enabled: false` |
| datamigratie | `keycloak.config.clients.datamigratie.oidcUrl` | `keycloak.config.clients.datamigratie.enabled: false` |

`openzaak.configuration.oidcUrl` and `objecttypen.configuration.oidcUrl` are
also the API base URLs of the `create-required-catalogi` and
`create-required-objecttypen` Jobs, so with the old defaults those Jobs called
`example.nl` too.

### Action required

Run `helm template` with the environment's values before the upgrade. For each
failure, the message names the exact value:

- Set the value to the public https URL of that component, or
- disable what the environment does not use. The `monitoring`, `datamigratie`
  and `zaakbrug` Keycloak clients are enabled by default even where the
  component does not run; set `keycloak.config.clients.<name>.enabled: false`
  there.

A disabled component or client is not checked at all, so it may keep its URL
set (real or placeholder); there is no need to remove it.
