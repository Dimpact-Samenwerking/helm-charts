# Upgrade guide: PodiumD 4.8.6 → 4.9.0

> See the Confluence Releases page for the agreed application
> targets: <https://dimpact.atlassian.net/wiki/spaces/PCP/pages/7602191/Releases+PodiumD>.

This is the upgrade guide for environments already on **4.8.6**.

4.8.6 was a single-purpose security patch on top of 4.8.5 (Keycloak
26.6.4 → 26.7.2 and the adfinis `keycloak-operator` chart 1.12.1 → 1.13.0 —
see [`4.8.5-to-4.8.6-upgrade.md`](4.8.5-to-4.8.6-upgrade.md)). Everything else
in 4.9.0 is identical to the 4.8.5 → 4.9.0 hop.

## How to read this hop

1. **Read [`4.8.5-to-4.9.0-upgrade.md`](4.8.5-to-4.9.0-upgrade.md) in full.**
   It is the substantive guide: KISS 3.0.0, ITA 3.3.0, Open Zaak 1.29.3,
   ECK 3.5.0 and the rest all apply unchanged to an environment on 4.8.6.
2. **Skip its "Keycloak app image 26.6.4 → 26.7.2" section.** You already
   run Keycloak 26.7.2 — 4.8.6 delivered it. The app image is the same in
   both releases (`26.7.2`, digest
   `sha256:9d1f1b2b7261ff53c66cb1092dfcdc34a5fb77e81f9e6a6e75b8b6a795de8067`),
   so this hop is a no-op for the Keycloak server.
3. **Read the Keycloak Operator section below.** This is the one place where
   4.8.6 → 4.9.0 differs from 4.8.5 → 4.9.0, and it is a **downgrade**.
4. Then follow the per-environment checklist in the 4.8.5 → 4.9.0 guide,
   and its companions:
   [values-deltas](4.8.5-to-4.9.0-values-deltas.md),
   [operators & CRDs](4.8.5-to-4.9.0-operators-crds.md),
   [gemeente-specific](4.8.5-to-4.9.0-gemeente-specific.md).

## Keycloak Operator: 26.7.2 → 26.6.4 (a downgrade)

4.9.0 was branched from 4.8.5 and never picked up 4.8.6's operator bump. The
two releases therefore disagree:

| | 4.8.6 | 4.9.0 |
|---|---|---|
| adfinis `keycloak-operator` chart | `1.13.0` | `1.12.1` |
| Operator image (`keycloak-operator.operator.image.tag`) | `26.7.2` | `26.6.4` |
| Keycloak **server** image (`keycloak.image.tag`) | `26.7.2` | `26.7.2` |

Upgrading 4.8.6 → 4.9.0 therefore **rolls the operator back** from 26.7.2 to
26.6.4 while leaving the server on 26.7.2. That combination is what 4.8.5 and
every release before 4.8.6 already ran, and it is what the 4.8.5 → 4.9.0 guide
describes ("operator stays put"), so it is a supported configuration — but note
that guide's reasoning ("no operator release yet supports Keycloak 26.7.x") was
overtaken by adfinis 1.13.0, which 4.8.6 ships.

### What this means in practice

- **The CRDs do not roll back.** Helm never removes or downgrades CRDs on
  upgrade, so the two CRDs 4.8.6 introduced
  (`keycloakoidcclients.k8s.keycloak.org`,
  `keycloaksamlclients.k8s.keycloak.org`) and the additive fields on
  `keycloakrealmimports` stay in the cluster after this hop. They are harmless:
  podiumd creates no CRs of those kinds, and the 26.6.4 operator simply ignores
  them. Leave them in place — deleting a CRD deletes its CRs.
- **The two extra `ClusterRole`s** templated by adfinis 1.13.0
  (`keycloakoidcclientcontroller-cluster-role`,
  `keycloaksamlclientcontroller-cluster-role`) are removed by the `helm
  upgrade`, since 1.12.1 does not template them. Expected; no action.
- **No security regression on the server.** The 23 CVEs 4.8.6 addressed are
  fixes in the Keycloak *server* image, which stays on 26.7.2.
- **Re-verify the operator digest before rollout.** 4.9.0 pins the 26.6.4
  operator via the adfinis chart's own bundled `operator.image.sha`, not an
  explicit podiumd override — the opposite of 4.8.6, which had to override it.
  Run `/verify-image-digests` against the target release.

### Action required

None beyond the normal 4.8.5 → 4.9.0 checklist. Do **not** hand-carry 4.8.6's
`keycloak-operator` values into a 4.9.0 environment: chart 1.12.1 does not
accept 1.13.0's `operator.image.sha` for 26.7.2, and pinning a 26.7.2 operator
digest onto the `26.6.4` tag renders an unpullable image reference.

> **Resolved in 4.9.1.** The 4.9 line is realigned on
> `feature/podiumd-4.9.1`, which carries adfinis chart `1.13.0` with both the
> operator and server images on `26.7.3`. So the rollback described here is
> temporary: it lasts only for as long as an environment sits on 4.9.0. If
> 4.9.1 is available when you plan this upgrade, prefer going straight to it
> and skipping the operator round-trip entirely — see the
> 4.9.0 → 4.9.1 guide once 4.9.1 is released.
