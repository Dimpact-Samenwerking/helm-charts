## Review

This is a pure version‑bump PR (KISS and ITA subcharts + their image pins, docs, and release metadata). The functional changes are internally consistent — every file agrees on KISS 3.1.3 and ITA 3.3.2, and all four image digests match across `values.yaml`, `README.md`, and `images-4.9.2.yaml`. No correctness or security defects in the rendered chart. The issues below are all metadata/doc inconsistencies.

**1. PR title/description say KISS 3.1.2, but the diff implements 3.1.3 (SELF‑CONTAINED, Medium, say‑do).**
The title ("KISS 3.1.2") and description ("KISS 3.1.1 → 3.1.2") contradict every file in the diff, which consistently uses 3.1.3 (`Chart.yaml`, `values.yaml`, `README.md`, `images-4.9.2.yaml`, `release-table.csv`, and the upgrade‑guide table all say 3.1.3). The weight of evidence says 3.1.3 is intended and the title/description are stale. If release tooling derives changelogs from the PR title, the 4.9.2 notes will state the wrong KISS version.

**2. Upgrade guide references a non‑existent values key `elasticSyncImage` (SELF‑CONTAINED, Minor, say‑do).**
The KISS section of `4.9.1-to-4.9.2-upgrade.md` says to set `kiss.settings.syncJobs.elasticSyncImage.tag`, but `values.yaml` (with the `# repository: .../kiss-elastic-sync` comment) and the regenerated `README.md` both show the elastic‑sync image lives at `kiss.settings.syncJobs.image.tag`. There is no `elasticSyncImage` key anywhere. An operator pinning the elastic‑sync image per the guide would set a key Helm silently ignores.

**3. `release-table.csv` KISS row lists only `kiss-frontend` (ASSUMED, Minor, simplification).**
Assuming `image_basename` is meant to enumerate a component's primary images (the ITA row lists both `poller,web`), the KISS row omits `kiss-elastic-sync`, which this PR explicitly bumps ("incl. kiss-elastic-sync"). Pre‑existing (the old row also listed only `kiss-frontend`), but worth completing now that the sync image is called out.

**4. `release-table.csv` Open Formulieren row looks stale (ASSUMED, Minor, correctness — pre‑existing).**
The OF row (context, unchanged by this diff) still targets 3.5.6, while `images-4.9.2.yaml` and the upgrade guide ship 3.5.8 for 4.9.2. This is not introduced here (the OF bump was a prior change) and may be handled by a separate OF PR, but since this PR claims to update `release-table.csv` for the 4.9.2 release, the mismatch is worth confirming.

No other issues: the new `verlopenContactverzoekHerinneringNotificatie` CronJob is correctly documented (enabled by default, `0 7 * * 1-5`, disable with `enabled: false`), and the shared `ita.poller.image`/`resources` structure is unchanged as stated.
